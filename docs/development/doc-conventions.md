# 文档写作约定

> **状态**：✅ 定型
> **来源**：2026-11-08 按 koc-code-docwriter 槽位规范整理 `docs/` 时，由旧 `docs/README.md` 第二节原样迁入
> **配套**：[文档索引](../README.md)（唯一索引与目录树）· 根目录 [`AGENTS.md`](../../AGENTS.md)

## 一、头部（`architecture/`、`features/`、`api/`、`data/` 下文档必带）

```markdown
# 文档标题

> **状态**：📝 待拍板 / 🔵 落码 / ✅ 定型
> **来源**：需求出处（用户原话 / 决策编号）
> **配套**：相关文档链接
```

`dependencies/` 下的另加 `**类型**`、`**适用版本**`、`**用途**`、`**版本真源**`、`**复核日期**`（写清是哪个包、哪个版本；宿主 / 官方升级后据此复核）。

## 二、命名

- `*-foundation.md` = 为什么这么设计；`*-guide.md` = 怎么做；两者内容不重复。
- 文档目录与文件名用纯 ASCII 小写 `kebab-case`，不带日期、不带版本号。

## 三、各槽位不得写什么

| 槽位 | 不得写 |
|---|---|
| `architecture/` | 进度、过程日志 |
| `dependencies/` | 猜测、未核实内容；不得写成「我们的设计」 |
| `features/` | 实现细节（归过程叙事） |
| 根 `README` 对外 | 内部设计 |

## 四、只链接，不摘引

文档之间、以及文档与外部规则之间，一律用链接指路 —— 不抄正文，也不用「见某文件第 X 节 / 第 X 条」这类编号定位：被引用方随时改版，抄来的和编号指来的都会过期。

## 五、配图

对外配图统一放仓库根的 `assets/screenshots/`（根 `README.md` / `README.en.md` 引用），不进 `docs/` —— `docs/` 根下只允许索引文件与槽位目录。
