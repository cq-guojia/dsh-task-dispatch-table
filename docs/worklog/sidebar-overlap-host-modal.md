# 两条侧边栏压住宿主「系统设置」弹窗

> **状态**：🔵 **已落码，⏳ 待真机复验**（2026-10-05）
> 日期：2026-10-05 ｜ 关联：`design/ui-foundation.md` §十 通用细则「层级 z-index」｜ 现场条目：`PROGRESS.md` §1.0

## 一、需求原话（用户 2026-10-05）

> 还是你克隆的那个插件：侧边栏没有挡住系统设置弹窗，也就是系统设置弹窗压在了侧边栏上面。
> 但是我们的两个侧边栏，不管是文件查看的还是任务编辑的，都把系统的设置弹窗挡住了，就压到系统的设置弹窗上了呀，我不知道是为啥。
> 找到问题，如果确定是 bug，就直接修改。注意不要影响到其他地方。

## 二、定位

两条侧边栏都是**占布局的分栏**，不是浮层——`archive-session-css.ts:22` 的注释自己就写着
「预览 dock：**占布局的分栏**（不是浮层）——它是根容器的 flex 成员，把整页真正挤窄」，
`index.ts:1089-1092` 同样强调「dock 是布局成员而非浮层 ⇒ 整页被真正挤窄」。

但两条规则却带着**浮层时代遗留的显式 z-index**：

| 规则 | 文件:行 | 原值 | 出处 |
|---|---|---|---|
| `.dsh-tdt-sv-preview.dsh-tdt-sv-preview-dock` | `archive-session-css.ts:26` | `z-index:1030` | `4a5086d`（U11 第三轮，预览面上提为页面级 dock） |
| `.dsh-tdt-ed-panel`（编辑抽屉） | `task-editor-css.ts:20` | `z-index:1040` | `38bf782`；`worklog/editor-split-pane.md:35` 记录它**当年确是浮层**（`.dsh-tdt-ed-overlay` = `position:fixed;inset:0;z-index:1040`），U21 改成布局成员后这个 1040 **没跟着清掉** |

**机制**（为什么显式 z-index 一定压过宿主弹窗）：本仓已核实的事实（见 `archive-session-css.ts:194-195`）
——官方 primitives `Modal` **portal 到 body**，「与本弹窗同 z-index 层、**后挂载居上**」。
「后挂载居上」只在**同一层**时成立。我们给了显式正 `z-index`，就把侧边栏抬到了独立层级，
宿主弹窗无论挂多晚、z-index 是多少（只要低于 1030 / 1040）都被压住。

反之，**去掉 z-index** 后两条侧边栏回到 `auto`，与宿主弹窗同层 ⇒ 由 DOM 顺序裁决 ⇒
portal 到 body 的宿主弹窗在后 ⇒ **弹窗回到上层**。这同时覆盖两种情况：宿主弹窗带显式 z-index（更大者胜）
或不带（DOM 顺序胜）。这也正是参照插件（better-sidebar）侧边栏不挡弹窗的原因。

补充核实：根容器 `#dsh-tdt-root`（`index.ts:1093-1102`）只有 `display:flex` 等布局属性，
**没有** `position` / `z-index` / `transform` / `isolation` ⇒ 不创建层叠上下文，
侧边栏的 z-index 直接在根层叠上下文里与宿主弹窗竞争，故上述分析成立。

## 三、改法（只动这两条，不波及其它）

| 文件 | 改动 |
|---|---|
| `archive-session-css.ts` | 预览 dock 规则去掉 `z-index:1030`；注释补「为什么不能有 z-index」 |
| `task-editor-css.ts` | 编辑抽屉规则去掉 `z-index:1040`；注释补「1040 是浮层时代遗留」 |
| `scripts/smoke.mjs` | 新增 2 条**反向断言**（两条规则不得带 `z-index`），钉住行为不被回退 |

**刻意不动**：`--tdt-z-*` 阶梯本身（`tokens.ts:146-151`）不动 ⇒ `--tdt-z-modal` 1070 / `-menu` 1100 / `-tip` 1200 等
自家浮层的相对次序零变化；`.dsh-tdt-sv-overlay`（1000）、拖拽条（7）、面包屑菜单（30/31）、
CodeViewer 复制钮（5）等局部层级一律不动。

⚠️ 顺带记录（**本轮未改**，避免扩大影响面）：`ui/Loading.tsx:25` 的 `zIndex: var(--tdt-z-dock)`（1030）
属同一类风险——它是 `position:fixed` 的右下角指示器，理论上也会压过宿主弹窗。
因它是瞬时小控件、且用户未报，本轮不动；若真机上发现它盖住弹窗，再单独处理（改它要同步确认不会沉到页面内容之下）。
