## 一、用户诉求与评估

用户原话（摘要）：

> 「这个附件是一个文件夹……里面甚至还有子文件夹，包含跑这个任务需要的代码（如 .py 文件）。所以我希望附件能不能支持文件夹？如果能支持，我就可以直接指令：『请用附件里面的文件夹里的什么什么来执行』」
>
> 追问（最关键的一句）：「我在提示词里面怎么跟大模型说呢？我就说『附件文件里的什么什么』，它能理解吗？这个你得想清楚，就是用户会怎么说，大模型还能找得到。」

评估给了三条结论：能支持；「选工作区目录」改动小、「本地上传文件夹」改动大一个数量级；主要影响是读取豁免扩到整棵子树。随后用户拍板三点：

1. **只做「选工作区里的目录」**，本地上传维持逐个文件；
2. **不给任务定义加目录标记字段**（用户原话「我觉得不用吧」）；
3. **不做任何安全加固** —— 本质就是给模型一个绝对路径让它自己找。

## 二、排查结论（动手前）

「目录」在现有链路上只有**两处**缺口，其余天然兼容：

| 环节 | 事实 | 结论 |
|---|---|---|
| zod schema `src/tasks.ts:96-112` | `ref` 只受 `isSafeAttachmentRef`（禁 `..` / 首位 `/` / 反斜杠）约束，多级相对路径合法 | 不改 |
| 缺失校验 `src/reconcile.ts:50`、`src/scheduler.ts:376` | `existsSync` 对目录同为真 | 不改 |
| 官方附件卡 `src/dispatch.ts:410-411` | `if (!info.isFile()) continue`，且宿主 `FileAttachmentRef` 没有路径字段 | 不改（目录永远只给路径） |
| 预览 `src/client/index.ts:1503` → FileBrowser dock | `file-browser.tsx:336-337`「list 成功 ⇒ 目录树」 | **不改（本来就能浏览）** |
| 服务端路径富化 `src/index.ts:422` | `join(来源工作区.path, item.ref)` | 不改 |
| **选择器** `src/client/file-browser.tsx:587` | 只有 `if (!isDir)` 才挂 pick；目录分支 `:608-628` 无回调 | **要改** |
| **注入** `src/dispatch.ts:365-375` | 所有条目长得一样，看不出哪条是目录 | **要改** |

> **更正一处自己早先的误判**：评估时说「目录点开预览会报错」——错的。`locales.ts` 里那条「这是一个目录，暂不支持目录浏览」属于**单文件预览组件**（`file-preview.tsx:365-368`，`read` 吃到目录时才会走到）；附件行的点开走的是 FileBrowser dock（`index.ts:1503`），后者本来就是目录树。⇒ 预览零改动。

## 三、落码清单

| # | 位置 | 改了什么 |
|---|---|---|
| 1 | `src/client/file-browser.tsx` `renderTree` directory 分支 | picker 模式下目录行**整行可选**：`onClick: pickDir` ⇒ `onPick(relativizeToRoot(childPath, sessionId))`；非 picker 仍 `loadDir`。加 `dsh-tdt-sv-tree-row-pick` 观感类 + 目录专用 title；▸ 展开自带 `stopPropagation`，不受影响 |
| 2 | `src/reconcile.ts:461-475` | ref → 绝对路径的构造改成 `await Promise.all(...)`，顺手 `stat(path).isDirectory()` 填 `isDir`；**失败即降级 undefined（按文件处理）**。`stat` 取 `node:fs/promises`（与 `dispatch.ts` 同写法） |
| 3 | `src/dispatch.ts:356-362` | `DispatchAttachment` 加**可选** `isDir?: boolean` —— 只在派发瞬间的内存里活，**不落库、不进快照** |
| 4 | `src/dispatch.ts` `attachmentLines` | 段头加「任务提示词里说的『附件 / 随附文件』就是指下面这些」；目录条打「（目录）」+ 路径尾补 `/`；清单里有目录时追加一句「按 `<该项路径>/<相对路径>` 拼出完整路径后再读取」 |
| 5 | `src/client/locales.ts` | 新增 `editorPickerPickDir`（中 / 英）；`editorAttachmentsHint` 中英两版补「可选整个目录 + 提示词里写『目录名/子路径』」 |
| 6 | `scripts/smoke.mjs` | 随附文件段加 4 条断言：目录标注与尾斜杠、相对路径规则句、段头接缝句、**纯文件清单不带目录规则句**（守旧行为） |

**刻意不做的**：目录专用文件夹图标（无扩展名的文件夹名本身就落到通用图标）、`.git` / `node_modules` 黑名单、选工作区根目录的兜底（树里没有「根」这一行，够不到）。

**为什么 `isDir` 不落库**：用户明确不要新字段。落库就要连带改 schema、快照解析、草稿回填与历史实例兼容；不落库则这些零改动，代价只是每次派发多 N 次 stat（N = 附件条数，且 `attachmentFileBlocks` 本来就要 stat 一遍）。

**为什么目录只存一条**：保存任务请求体上限 1MB（`DISPATCH_BODY_LIMIT`，`src/index.ts:215`），展开成文件列表会撞 413；且注入的 prompt 会随文件数线性膨胀，违背「文件夹多大都不多吃 token」。

## 四、验收清单（真机）

1. 任务表单「附加文件」→ 方形「选择工作区文件」按钮 → 目录行点整行 ⇒ 附件列表多一行，**名字就是文件夹名**；▸ 仍只管展开，点目录不会导航进去。
2. 保存成功后该行**可点开** ⇒ 右侧 dock 显示该目录的树（子文件可直接点开预览）。
3. 立即执行该任务 ⇒ 打开会话看用户消息：应出现 `- <文件夹名>（目录）：<绝对路径>/`，并在下方有一句「按 `<该项路径>/<相对路径>` 拼出完整路径后再读取」。
4. 任务提示词写「用附件里的 `<文件夹名>`/`<子文件路径>` 执行」⇒ 模型应自己找到并读取该文件。
5. 回归：普通文件附件的注入仍是一条路径 +（上传 / 工作区）标签；目录不出现在会话的官方附件卡里（官方附件只认字节）。
6. 把该目录删掉后再跑同一任务 ⇒ 仍走老的 `attachment-missing` 拦截（不执行 + 留痕）。
