## 四、界面形态：候选与约束（→ Q1）

**硬约束**：

- 整页已由我们自己的 `main` 槽承载（任务列表 + 三标签），**右侧已被页面级预览 dock 长期占用**（U11 分栏推压，宽度变量 `--dsh-tdt-preview-w`，用户可随时拉出 / 收回）⇒ **右侧抽屉与预览面同侧冲突**：同时打开时谁让位、谁压谁必须先定义。
- 官方 primitives 可用 `Modal` + `Button`（已核实，已用于 fork 确认框），但**没有表单控件**（`primitives.d.ts` 只有 Modal / Button / Tooltip / StateDot / DisclosureRow / 图标等）；现有面板的表单件是**原生 `<select>` + 内联样式 + `--dsw-alias-*` token**。

| 候选 | 优点 | 代价 |
|---|---|---|
| **A 整页内表单视图**（列表 ⇄ 表单，带「← 返回任务列表」） | 宽度充裕，放得下「提示词大框 + 频率 + 依赖」；与预览 dock 天然共存（内容区被挤窄，dock 不动） | 不是浮层，创建时看不到列表上下文 |
| **B 居中弹窗**（官方 `Modal`） | 复刻官方观感；创建 / 编辑不离开列表 | 表单较长（频率 + 依赖 + 版本历史），弹窗高度吃紧；与预览 dock 叠加成两层浮层 |
| **C 右侧抽屉** | 用户提名，与图 1 同形 | **与预览 dock 同侧冲突**（硬约束）；窄栏放不下大输入框 |
| **D 左侧抽屉** | 避开 dock 冲突 | 用户没提，方向性偏差 |

**倾向（待拍板）**：A 为主形态；B 只承担「改启停 / 改频率」这类**单字段小改**（或直接列表行内改）。

## 六、字段 → 控件映射

字段真源 = `taskDefinitionSchema`（`src/tasks.ts:24-63`）。

| 字段 | 控件 | 备注 | 数据来源 |
|---|---|---|---|
| `id` | **不可见**（隐藏透传） | 创建时**不带 id**（闸门补 UUID）；编辑时原样带 UUID | 本地 |
| `title` | 文本输入 | 可缺省（回退显示 id） | 本地 |
| `code` | 文本输入（可选） | 人读编号，trim 后空白 = 未填 | 本地 |
| `enabled` | 开关 | 停用不删定义 | 本地 |
| `schedule.cron` / `schedule.once` | **频率选择器**（预设 + 自定义 cron，互斥） | 预设选项要**反显 cron 原文**（图 1 同款）；once = 日期时间选择器 | 本地 |
| `schedule.timezone` | 下拉 | 缺省 = 宿主时区 | 宿主时区列表（待定） |
| `schedule.window` | 「有效期」下拉（PT30M / PT2H / PT4H / 长期…） | 语义：窗口只管开始 | 本地 |
| `target.workspace` | 下拉（按工作区 **title** 精确匹配） | 匹配不到 ⇒ 实例判失败 | **需工作区列表数据面** → §九.2 |
| `target.provider` / `target.model` | 下拉（**成对**，只填一个视为没配） | 留空 = 走四层漏斗 | **需模型列表数据面** → §九.2 |
| `target.manual` | 文件选择器 | 见 Q4（是否等同于「提示词文件」） | **需工作区文件树数据面** |
| `target.prompt` | 大输入框 / 文件引用 | 主视觉 | 本地 |
| `contract.validStatuses` | 高级：多值 | 默认 `["ok"]` | 本地 |
| `retry.maxAttempts` | 高级：数字 | 默认 1 | 本地 |
| `depends_on[]` | 依赖编辑器：选任务 + 语义 | 语义只有 `same_period` / `latest_success` 两种（`freshness` 已由决策 33 删除） | 任务列表 |

## 七、创建 vs 编辑（R6）

- **创建**：单页基本信息；保存时条目**不带 `id`** ⇒ 闸门生成 UUID 固化（`src/tasks.ts:173-176`）。
- **编辑**：带 UUID ⇒ 必须命中现有已保存任务表，否则**整批 422**（`src/tasks.ts:180-187`）；两 tab：**基本信息 / 执行记录**（执行记录直接复用现有那张表，按 `task_id` 过滤）。
- **列表侧**（→ Q2）：每行「编辑」入口 + **行内启停开关**（快速改，不必进表单）。

## 八、提示词来源与版本管理（R8–R13）

### 三种来源（→ Q4 / Q5）

| 来源 | 落地形态 | 是否纳入版本管理 |
|---|---|---|
| ① 直接输入 | 文本存 `target.prompt` | ✅（R10） |
| ② 引用工作区文件 | 今天语义最接近的是 `target.manual`：调度器只把**路径**拼进派发消息，agent 自己去读 → **内容不进任务定义** | ❌（R13） |
| ③ 上传 MD | 内容落到哪待定：插件存储 / 复制进目标工作区 | ✅（R10） |

⚠️ **Q4 是关键歧义**：「选一个提示词文件」如果 = 复用 `target.manual`，则**行为是「agent 去读那个文件」**（文件是活的手册，改文件即改行为）；如果用户想要的是「**文件内容就是提示词本体**」（= 派发时把内容并进消息），那是**另一个字段 / 另一种模式**，两者行为与版本语义都不同。

### 版本库：存储候选（→ Q6）

| 方案 | 形态 | 优劣 |
|---|---|---|
| A | state.db 新表 `prompt_versions(task_id, seq, ts, source, content)` | 与实例库同生命周期（跨重装 / 容器重建存活）、可 SQL 清理、可查询 |
| B | `meta` 表里存 JSON 文本 | 零 DDL；整块读写、无查询、易被整段覆盖 |
| C | 独立本地 git 仓库（一版一 commit） | 天然 diff / 回滚；需容器内有 git，且要处理路径 / 凭据 |

### 保留策略（→ Q7）

按天（如 3 天）/ 按条数（最近 10 / 20 版）/ 两者结合（先按条数封顶，再按天数清）。体积据 R11 不敏感，**不做**压缩 / 去重也可以。

## 九、落码前提（数据与接口缺口）—— 硬阻塞

1. **快照投影要扩**：`GET /snapshot` 的任务明细今天只有 10 个字段（`src/index.ts:395-414`），表单要的 `prompt / provider / model / manual / retry / depends_on / contract` **一个都没有** ⇒ 必须扩投影（或另开只读接口）。
2. **工作区列表、模型列表没有数据面**：`target.workspace` 按工作区 **title** 精确匹配 ⇒ 下拉必须列**宿主真实工作区**；模型要 provider/model **成对**。需先核实宿主 API（workspaceRegistry / llm 相关服务）并新增读取通道——按仓库规矩**先读源码再动手**。
3. **前端没有 TaskDef 类型**：本仓库 client 不引宿主类型（惯例注释见 `src/client/index.ts:349`）⇒ 需要一份与 `taskDefinitionSchema` 对齐的**镜像类型**。
4. **表单 → JSON 往返必须无损**：保存仍是「整段 tasksInline JSON」；表单只认识自己暴露的字段 ⇒ **未暴露 / 未来新增的字段必须原样保留**，否则一次编辑就静默删配置（这是本工作包最容易埋雷的一条）。
5. **草稿 vs 2s 轮询**：客户端每 2s 拉快照（`src/client/index.ts:1134`）⇒ 编辑期间必须防止快照把用户草稿冲掉（脏标记 / 暂停覆盖 / 合并策略）。
6. **JSON 通道去留**（→ Q3）：建议保留为「高级 / 逃生通道」，避免表单覆盖不全时的死路。
7. **i18n**：所有新文案要同时进 `locales.ts` 的 `zh` / `en`（`src/client/locales.ts:108/362`）。

## 十一、动工前必须守住的既有不变量

- **保存闸门（决策 30）**：新增不带 id / 带 UUID 即修改且必须命中现有表 / 非 UUID 整批拒。
- **任务定义仍存 tasksInline**（meta 主通道），**不进数据库**（决策 6）。
- **字段语义不改**：`cron` 与 `once` 互斥；`workspace` 按 title 匹配；provider/model 成对；`window` 只管开始；依赖语义只有 `same_period` / `latest_success`。
- **版本管理是新增能力**，不得改变派发链路对 `target.prompt` 的读取语义（`dispatch.ts` 的 `buildMessage`）。
- **正常功能一律真实取数**：工作区下拉、模型下拉、文件树都必须来自宿主真实数据面，不得硬编码 / 假数据。
