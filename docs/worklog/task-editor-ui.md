## 四、形态定稿（Q1 ✅ 弹窗）

### 外观

| 项 | 定成什么样 |
|---|---|
| 位置 | **右侧贴边**，上下顶满（页面最顶到最底） |
| 宽度 | 默认 520–560px；**左缘可拖拽**调宽（有上下限） |
| 盖不盖 | **浮层盖在页面上**，页面**不推压、不变窄** |
| 遮罩 | 半透明遮罩（观感与官方弹窗一致）；点遮罩 / Esc / 右上角叉 都能关 |
| 与预览面的关系 | 弹窗盖住整页（含预览面）；预览面**不收回**，关掉弹窗它还在原位 |
| 内部滚动 | 内容长就在弹窗内部滚；底部「取消 / 保存」**固定在最下面** |
| 组件来源 | 外壳自绘（官方 `Modal` 只居中）；按钮 = 官方 `Button`，色值 = `--dsw-alias-*` token |

### 硬约束（为什么不是推压）

- 整页右侧已被**页面级预览 dock 长期占用**（U11，那是**占布局的分栏**，变量 `--dsh-tdt-preview-w`）。用户澄清：他要的「右侧拉篮」是**盖上去的浮层弹窗**，与预览 dock 那种推压分栏**不是一回事**，两者不冲突（弹窗在 overlay 层，dock 在其下）。
- ~~官方 primitives 有 `Modal` + `Button`，但**没有表单控件**（`primitives.d.ts`）~~ ❌ **2026-09-29 纠正：结论错误**。真相 = 官方**有一整套表单件**（`Switch` / `Input` / `Checkbox` / `SegmentedControl` / `SegmentedTabs` / `Menu` / `Pill` / `Tag` / `Toast` / `ConfigField` / `SettingsForm`），我们那份 `primitives.d.ts` 只是「当前用得到的最小消费面」，**不是官方全景**；真正**没有**的只有**日期 / 时间选择器**。核实法：`npm pack @deepseek-ai/dsh-client-ui-primitives@0.1.7-rc.2` 读 `lib/types/**` + `lib/index.js` 导出清单（已沉淀进 [`design/dsh-capabilities.md`](../design/dsh-capabilities.md)「已关闭的源码核实项」）。⇒ **控件一律改用官方**（下拉 = 官方 `Menu` 带对勾、开关 = 官方 `Switch`、分段 = 官方 `SegmentedControl`、chip = 官方 `Pill`），只有日历与时分列自绘。**教训：判断「官方有没有某件」必须读包本体，不能拿本仓库自写的 `.d.ts` 当依据。**

## 七、创建 vs 编辑（R6）

- **创建**：顶部只有「基本信息」；保存时条目**不带 `id`** ⇒ 闸门生成 UUID 固化（`src/tasks.ts:173-176`）。
- **编辑**：带 UUID ⇒ 必须命中现有已保存任务表，否则**整批 422**（`src/tasks.ts:180-187`）；顶部两 tab：**基本信息 / 执行记录**（执行记录复用现有表，按 `task_id` 过滤）。
- **入口**：整页**右上角**（现有刷新按钮 + 三标签分段控件那一片）加「**+ 新建任务**」按钮拉起弹窗；任务表每行「编辑」入口 + 行内启停开关（→ Q2）。

## 八、提示词来源与版本管理（R8–R13）

### 三种来源（Q4 ✅）

| 来源 | 落地形态 | 版本管理 |
|---|---|---|
| ① 手敲 / 粘贴 | 文本存 `target.prompt` | ✅ 我们管 |
| ② 选工作区里的文件 | **= `target.manual`，只记路径**，派发时 agent 自己去读；内容不进任务定义、随时改随时生效 | ❌ 用户自己管（R13） |
| ③ 上传 MD | 内容落到插件存储（P3 定） | ✅ 我们管 |

### 版本库：定为**文件版**（Q6 ✅）

```
storages/dsh-task-dispatch-table/prompt-versions/<taskId>/
  001-20260928-1430.md       ← 该版提示词原文
  002-20260928-1810.md
  index.json                 ← 版本清单：第几版 / 时间 / 来源（手敲 or 上传）
```

**为什么不用 git**（用户问「官方包里有没有 git、没有能不能装」）：

1. 官方包里**没有** git。
2. **不该装**：插件跑在 DSH **容器**里，那容器非常精简——已核实**没有 `sqlite3` / `file`**（`docs/design/dsh-capabilities.md:19`）、**没有 curl**（`docs/PROGRESS.md:133`）；我们连 SQLite 都只能用 node 内置的 `node:sqlite`，就是因为容器里没工具。**容器里装什么是部署侧的事，插件决定不了，且容器重建即丢**。
3. 「容器里到底有没有 git」目前**无实测结论**（下次真机可顺带探测一次），但**不该押在它身上**。
4. 真要 git 语义也有退路（把纯 JS git 库打进包里），但为存几版提示词引入一整个 git 太重。

**文件版的好处**：不依赖任何外部二进制（node `fs` 就够）；与决策 6「任务定义存文件、不入库」同构；用户能直接打开文件夹看（用户认可）；备份 / diff / 回滚都方便。两版对比的渲染可复用客户端已有的官方 `DiffBlock`（`src/client/primitives.d.ts:254`）。

### 保留策略（→ Q7）

按条数封顶（如 20 版）+ 按天（如 30 天），清理 = 删旧文件。体积据 R11 不敏感。
