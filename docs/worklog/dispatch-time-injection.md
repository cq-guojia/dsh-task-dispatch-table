# 派发消息注入「执行时间」（U4 收口）

> ✅ **完成封卷**（2026-10-05 当日拍板、当日落码，冒烟 625/0）。
> 现场记录见 [`PROGRESS-HISTORY.md`](../PROGRESS-HISTORY.md)。

## 一、背景（U4 原始问题）

真机 once8 实例：调度时刻 2026-09-23，agent 产出的文件却叫 `work-report-2026-09-24.md`——日期差了一天。派发消息里没有写「今天是几号」，模型对当前时间的感知未必可靠（跨天时刻执行、时区、模型自算都可能出错）。

讨论中用户点破了关键分界：这件事有两层——

- **事实层**（现在是几月几号几点几分）：插件手里有准确答案，应该给；
- **语义层**（这份日报算调度那天还是自然天）：插件解决不了，也不该它解决，只能由任务提示词自定。

## 二、拍板（用户 2026-10-05）

派发消息注入**执行时间两条**，只给事实、不给语义：

1. **原定执行时间**（实例的 `scheduled_at`，ISO 8601 / UTC，精确到秒）；
2. **实际派发时间**（send 前现取，ISO 8601 / UTC，精确到秒）。

并声明「你的当前时间以实际派发为准」。模型拿到后要怎么处理自己处理——用户原话方向：「它自己就能知道当前执行的时间了」「自己处理吧」。

## 三、落码

| 位置 | 改动 |
|---|---|
| `src/dispatch.ts` | `buildMessage` 加可选参 `times?: { scheduledAt; dispatchedAt }`；给了就在「任务实例」行后注入一行 `执行时间：原定 … · 实际派发 …（ISO 8601，UTC；你的当前时间以实际派发为准）`；不给 ⇒ 不注入（旧调用 / 旧行为不变） |
| `src/dispatch.ts` `dispatchTask` | send 前传 `{ scheduledAt: input.scheduledAt, dispatchedAt: new Date().toISOString() }` |
| `scripts/smoke.mjs` | +2 断言：① 传 times ⇒ 三要素进消息；② 旧调用（不传 times）不带该段 |

「任务实例」行里原有的 `logicalDate`（任务时区的业务日期）保持不变——它是日期语义层的锚点，与本次注入的时刻事实互补。

## 四、验证

- build 过（host + client）；
- 冒烟 **625 项通过 / 0 失败**（+2）。

## 五、不做的

- 不注入任务时区的本地化时刻（快照不带 timezone，决策 41「只读快照」不破）——ISO UTC 无歧义，模型可自行换算；
- 不规定产出文件名 / 正文的日期格式——那是任务提示词的事。
