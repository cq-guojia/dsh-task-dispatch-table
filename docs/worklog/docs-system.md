## 2026-09-25 (17) — PROGRESS.md 三层重构（109KB → 11.5KB）

**问题**：`PROGRESS.md` 自称「唯一进度真源」，但进展日志一路往下追加，滚到 109KB ⇒ 接手时读不完，真源退化成流水账。

**做法**：按**信息寿命**分三层 —— **现场层** `docs/PROGRESS.md`（短命、就地覆盖、恒定小）／**叙事层** `docs/worklog/<工作包名>.md`（一工作包一文件，做完标「✅ 完成封卷」、此后不再改）／**定型层** `docs/design/*.md`（长命，只留结论与理由）。

**落地**：109KB → 11.5KB；16 段进展日志拆成 8 个 worklog 文件（零丢失）；决策 25 / 30 的过程叙事挪进对应 worklog，`decisions.md` 只留结论；DSH 能力事实清单升格 [`design/dsh-capabilities.md`](../design/dsh-capabilities.md)；`AGENTS.md` 改写文档维护规则。纯文档变更，未跑冒烟。

## 2026-09-25 (18) — 公用规则外提为 RULES.md 真源（六轮纠错定稿）

用户给出自己工作室版的公用规则全文，要求：**凡所有工作区都用得上的规则**提炼成同级 `RULES.md`；`AGENTS.md` 只写本仓库独有的东西。定稿四节：〇 写操作闸门（含 Hindsight 知识页不得自建）／一 git／二 协作规矩／三 文档体系（固定目录 + 三层职责 + 每次推进的标准动作 6 步 + 6 条规则）。

过程中六轮纠错，**全部是「agent 凭常识补全、实际与用户口径不符」**：

1. **不许拿工作室口径套本仓库**：本仓库是 Git 仓库，文件随仓库提交入 Git、**从 Git 取用**，没有 NAS 双向同步；共用者是 CodeBuddy / TraeCode / DSH 等 coding agent（不是 WorkBuddy / 豆包工作）。
2. **AGENTS.md 与 RULES.md 必须完全脱耦**：`AGENTS.md` 不许复述、摘引、指代 `RULES.md` 的条目与序号 —— **写 AGENTS.md 的 agent 根本不知道 RULES.md 写了什么，引用无从谈起**。唯一耦合点是顶部 `<!-- ==== RULES BEGIN ==== -->` / `RULES END` 程序注入块（块内说明：公用规则全文在同级 `RULES.md`，会话开始前必须完整读取）。
3. **删「文件产出规范（`YYMMDD/HHMMSS-分类-描述.ext`）」整节**：那是**非开发工作区**的规则（那边常产出 TXT/MD 散文件）；这里文档位置已由文档体系规定、其余是代码，不存在「按时间/分类生成文件」⇒ 改为「源码 / 配置 / 依赖 / 构建产物一律走仓库既定布局，不适用任何自创命名规范」。同时**文档体系本身归公用规则**（只要是这个项目就一定这样摆，不该由各项目自创）。
4. **git 节收敛为单一开发者口径**：「说提交 = `commit` + `push` 一次做完」，不主动提交、不问「要不要提交 / 这个文件要不要留」；**绝不做网络层 workaround**（不配代理、不改 remote、不动凭证链），推不上去原样报告错误。`.gitignore` 沿用「改需明确指令」，但不套工作室那套严格白名单（那边产出物默认不入库，这里无须那么严）。
5. **长期记忆边界改写**：原先写「项目文档不进长期记忆」**是错的** —— 真实约束是**不许 agent 自建知识页**、**不许拿知识页当工作现场**（「下一步做什么」一律以 `docs/PROGRESS.md` 为准，知识页不稳定）；提交 / 上传文档不受此限，该记的照记。
6. **抬头删掉「适用范围」整句**：不写「只服务开发型项目」—— **只有开发型项目才会引用本文件，非开发项目根本读不到**；写上去反而逼 agent 每次自我分类「我算不算开发型项目」，想错就出问题。

**结论**：规则文件只写规则本身，**不做自我受众声明**；拿不准的边界（属于公用还是本项目独有）宁可写进本项目那侧。

## 2026-09-25 (19) — AGENTS.md 瘦身为薄壳（80 → 35 行）

结构只剩三块：顶部注入块（程序维护）＋ `一、接手流程`（读现场 → 动手前 → 干完回写）＋ `二、本仓库独有的约定`（dist 入库 / 冒烟 / 远端 SSH 直连）。

**删掉「三、仓库布局」整棵树**：与 `RULES.md` 三节的「固定目录」重复，且每加一个 worklog 文件就要改一次、`ls` 一眼可见 ⇒ 纯维护负担。同时确立：**`docs/` 之外的结构（源码 / 脚本 / 构建产物 / 配置）不由规则规定、也不在任何地方重复登记**。

**证据**：`AGENTS.md` 内 grep `RULES` 只命中注入块一行；全仓库 grep `开发型|开发项目|非开发|开发类` 零命中。
