## 一、需求原话（用户 2026-10-05）

> 「新增日历日程功能：希望做一个像日历一样的界面，用来展示任务的执行情况。比如，我能查到去年某一天执行了哪些任务；也能查到未来（比如明年 10 月 1 号）计划执行哪些任务，以及现在的计划安排得怎么样。……是单独放一个滑轨出来吗？比如现在有一个叫『任务配置』的，另外有一个『执行记录』，再单独加一个叫『任务日程』的？然后专门去做一个日程表，以一个月为维度，把这个月的日历显示出来。在日历上标记出我执行成功的、执行失败的、即将执行的，或者跳过的，把这些都填到日历里面去。」

同轮用户另提了「重构调试界面」，并明确**先做日历** ⇒ 本工作包只做日历，调试页不动。

我的建议与用户拍板的四条：

1. **新增独立第四个一级 tab「任务日程」**，不塞进「执行记录」里做「列表 / 日历」切换（理由：两者数据源根本不同 —— 记录查库、日程还要现算未来；分页与过滤语义也不同；且「执行记录」字面就该是已发生的）。
2. 未来计划**只算已启用任务**。
3. 过滤照常给（工作区 / 任务 / 状态），**日期维度不用时间范围控件**，改成月份翻页。
4. 月份可自由翻到任意过去月与未来月。

## 三、落码过程

### 3.1 新增独立 tab（`src/client/index.ts`）

- `tab` 联合类型加 `'calendar'`，`Segmented` items 加第四段。
- 渲染分支**排在 `data === undefined` 门槛之前**（照 2026-10-04 那次事故留下的注释：不吃调试快照的页面放在门槛之后，会被快照缺失一起挡掉）。
- 数据复用页面已有的 `overview.rows` 与 `timelineTasks`，不让新页自己去拉任务定义。

### 3.2 服务端：给既有路由加 `light=1`（本功能唯一的服务端改动）

- 动因：实例行带 `snapshot` 列（派发快照，单行 1.5–4 KB）；整月几百到上千行一次取，带它就是数 MB。
- 做法：`store.ts` 抽出 `instanceWhere`（全量与轻量**共用同一套过滤条件**，SQL 条件不写第二遍）+ 新增 `listInstancesLite`：显式列清单剔除 `snapshot`、上限 **3000**、不分页、触及上限回 `truncated`。既有 `listInstancesByQuery` 的 500 上限与游标语义**一个字都没动**（记录页分页依赖它）。
- `attachNotes`（失败 / 跳过原因）**保留**：它只对终态行做一次 IN 查询，日历的清单要靠它显示原因。
- 不做 `session_title` 富化（那要逐行 `JSON.parse(snapshot)`）；日历的任务名从任务定义本地映射。

### 3.3 纯计算核 `src/calendar-plan.ts`（服务端与浏览器同一份，可被冒烟直接测）

- `planEntriesByDay(tasks, from, to, now)`：输出按本地日分桶的计划条目。
- **三条硬规矩**：只算 `enabled` 的任务；只列 `>= now` 的刻度（**不回填过去** —— 拿现在的定义去回填过去会造出从未发生过的执行）；`once` 出窗口即作废（决策 18 / 拍板 A）。
- **按自然周分片调 `scheduledSlotsFor`**：`cap` 是**单次调用**的迭代上限，每分钟档整月约 44640 个刻度，整月一次算会被**静默截断**（表现为「月底那几天凭空消失」）。分片是半开区间 ⇒ 不重不漏。
- 网格算法**不自己写**：`buildMonthCells` 从 `ui/DateTime.tsx` 上提为导出，日期框的自绘日历与日历页共用（我最初在 `calendar-plan.ts` 里写了一份 `monthGridOf`，随即删掉 —— 那是第二份实现）。

### 3.4 页面 `src/client/task-calendar.tsx`

- 过滤行 / 状态档 / 工作区 / 任务选择器全部复用既有单源（`Segmented` / `SelectField` / `TaskPicker` / `statusesOfBucket` / `statusToneOf` / `statusTextOf` / `calendarLabelsOf`）。
- 两态区分：已发生 = 状态色实心点（+ 清单里的状态色浅底），计划 = 虚线空心点 + 虚线描边 + 悬停说明。
- 点某天**不发起请求**（整月行已在内存）。
- 计划重算用**排期指纹**做依赖（overview 是 10 秒轮询的，每次都换出新数组引用 ⇒ 不能让每次轮询都把几十个任务的 cron 解析重跑一遍）。

## 五、真机反馈 r1：一个任务都读不出来（2026-10-05 当天）

**现象**：用户装上新 dist 打开「任务日程」，格子里一条记录都没有（历史记录是有的）。

**根因**：`monthRangeOf` / `monthRangeQuery` 的 `month` 参数是 **0-based**（照 `Date` 的惯例写的），而日历页的 `cursor.m` 是 **1-based**（`getMonth() + 1`，与 `buildMonthCells` / `monthTitle` 同口径）⇒ 页面显示 10 月，取数却查了 **11 月**的区间；未来的计划刻度同样错一个月。字符串比较本身没问题（库里 `scheduled_at` 是 `toISOString()` 的 Z 格式，与 from/to 同格式），纯粹是月份错位。

**修法**：两个函数改 **1-based**，与日历页另外两个月份 API 统一（日历里所有「月份」参数一律 1-based），函数头写明并把这次事故写进注释；冒烟断言改成「传 10 = 十月」并加 `getMonth() === 9` 的反向断言守着。

**教训**：同一页面里「月份」这个参数出现了三处（网格 / 标题 / 区间），其中两处天生 1-based（UI 惯例），第三处照 `Date` 写成 0-based ⇒ 必然踩。以后凡是跨「Date 原生」与「UI 展示」的月份参数，一律跟 UI 走 1-based 并在签名上写死。

## 六、真机反馈 r2：交互改造（2026-10-06）

用户看到记录后提了六条，逐条落码：

1. **格子内要显示全部**（不管有多少任务），且「我甚至认为名字都不需要，一个时间就是一个任务」 ⇒ 格内只留 `HH:mm` + 状态色小点，**删掉 `MAX_CELL_ITEMS` 与 `+N`**，任务名与状态名移到悬停说明（`title`）。
2. 点时刻弹右侧栏看执行详情 —— 用户自己当场搁置（「执行记录现在没有右边弹出的东西」），**本轮不做**。
3. **点某天不再是下方清单**，改成**那一天所在的那一周像手风琴一样拉开**（跨 7 列的面板插在该周下面），当天全部执行信息铺在拉开区里；**有多少显示多少，不设内部滚动条**。
4. 拉开区里的执行信息「有点像前面那个任务执行记录……该展开能展开，展开后前置任务、产出等内容都应该出现」 ⇒ **复用 `records-timeline.tsx` 的 `RecordItem`**（2026-10-06 提为导出 + 抽 `RecordItemProps` + 新增幂等 `ensureRecordsStyle()`），**没有重写第二份条目渲染**。
5. **去掉状态分段过滤**（全部 / 成功 / 失败 / 运行中「没有意义」）。
6. 右侧布局：工作区 + 任务选择保留，**与月份导航 / 今天同一行、居右**；「已执行 / 计划 / N 条」放在这两个框**左边**。

**配套取舍**：拉开区要显示前置 / 产出，而整月取的是**轻量行（无 snapshot）** ⇒ 展开某条时按会话 id 走既有 `fetchInstanceBySession` 补一次全量行拿 `snapshot` + `fetchEvents` 取事件流水（零新接口）；无会话 id（skipped 之类没派发的）⇒ 本来就没有前置 / 产出，**不补也不假装有**。

## 七、真机反馈 r3：格子改成方形标签 + 拉开动画 + 网格线（2026-10-06）

用户看完 r2 提的：

1. **不要圆点，要方形小标签**：「前面一条 3 个像素的深绿色竖线，后面是浅绿色，里面写上时间，标签之间隔几个像素」。⇒ 格内条目从「圆点 + 时间」改成 `.dsh-tdt-cal-tag`（3px 状态色竖线 `::before` + 同色系浅底 + 时刻）。
2. **格子定宽定高**，标签按固定格位排：算下来 **一行 3 个 × 3 行 = 9 个位子**，前 8 位放时刻，第 9 位放 `…N`（剩余条数）—— 这是给用户的建议并被采纳：格子宽度会随窗口在 760–1120 之间变，只有固定格位才能保证「一样宽一样高」时不出现半截行。
3. **拉开要有很短的小动画**（不能瞬间弹出）⇒ `.dsh-tdt-cal-panel` 加 180ms `max-height + opacity` 展开动画（max-height 上限只作动画期裁剪，结束即恢复 `none`）。
4. **选中的那一格底色要不同** ⇒ 用基础层既有的 `--tdt-open-bg` + 品牌色描边（不是白底也不是白框），拉开区顶部再加一条品牌色顶边接上。
5. **每一格都要有线**（此前只有补位格之间有线，普通格子在暗色下糊成一片）⇒ 连片网格改成**独立卡片式**（1px 描边 + 微圆角 + 6px 间隔），参考 Google / Apple / Notion 月视图；表头下方加一条细分隔线。
6. 「整体再好看点」⇒ 同上卡片化 + 今天圆底数字 + 图例改成与格内标签同款的色块（`.dsh-tdt-cal-swatch`）。

**踩坑**：CSS 写在 JS 模板字符串里，注释中不能出现反引号（会提前终结字符串）—— 两处注释里的 `` ` `` 直接把 typecheck 打成 TS1005，改成普通写法。

## 八、真机反馈 r4：方就是方、蓝就是蓝（2026-10-06）

用户对 r3 的观感「一言难尽」，逐条点名：

1. **日历块要纯粹的正方形，不要圆角**；**只留 1px 间隔**；**本月格与相邻月补位格高度必须一模一样**。
   ⇒ 去掉格子的圆角与描边，网格回到 `gap:1px` + 容器底色透缝当线；底色区分三态（surface-1 / surface-2 / open-bg）；统一 `box-sizing:border-box`（补位格是 `div`、本月格是 `button`，盒模型不统一就会差 2px —— 高度不一致的真因）。
2. **标签**：不要任何圆角（去掉 `border-radius:2px`）；**底色太浅看不出来** ⇒ 从基础层 `-soft`（8%）调深到 **24%**（只在本域局部变量上调，不动 `ui/tokens.ts` 的 token）；**文字要在竖线后面的底色里居中**（`>span{text-align:center}`）；左右留白与标签间距都取 **2px**。
3. **选中与拉开都用蓝色**（不是绿色），且**不要任何白边 / 圆角 / 边**：选中格 = `--tdt-open-bg` 蓝底，拉开区 = 同一块蓝底、无圆角无边框，`margin-top:-1px` 吃掉网格那 1px 行间距 ⇒ 与上面那一格**连成一片**（视觉上就是「从那一格拉出来的」）。

**踩坑（第二次踩同一个）**：CSS 写在 JS 模板字符串里，注释中**不能出现反引号**（会提前终结模板字符串）⇒ 两处注释里的 `` `box-sizing:border-box` `` / `` `margin-top:-1px` `` 直接把 typecheck 打成 TS1005。**改这类注释时先确认不在模板字符串里。**

**另修一个隐性冲突**：拉开区的「计划」小字 / 条数原本也用 `.dsh-tdt-cal-tag` 类名，与格内标签类**同名** ⇒ CSS 后定义的 `flex:none` 会盖到格内标签上（标签撑不开）。已拆成 `.dsh-tdt-cal-mini`。

## 九、真机反馈 r5：展开指示改「内框线」+ 计划行补全信息（2026-10-06）

1. **整块蓝底太丑** ⇒ 按用户的建议改：**底色恢复正常**，展开指示改成「**离边 3–4px 的亮蓝内框线**」—— 用 `outline` + 负 `outline-offset` 画（不占布局、格子尺寸不变），选中的那一格（-3px）与拉开区（-4px）同一套语言，颜色统一 `--tdt-business`。之前的 `margin-top:-1px` 连体方案随之撤销（不再需要连成一片）。

## 十、真机反馈 r6：线是「两条横线」不是一圈框（2026-10-06）

我 r5 把用户的意思做成了**整圈内框线**，用户当场纠正（附截图）：

> 「我不是整个框都把它框起来，就是在当前的那个时间上面加一条，在展开的那一块上面加一条，而且还要把当前日期的那一块空开。」
> 「你那个线的高度…至少要放到 5。你的内间距也不够…至少也得到 4 或 5。」

改正：

1. **两条横线**（不是框）：① 选中日所在那一行的**上方**；② 拉开区的**顶部**。选中格自身**不加任何框**，底色保持正常色。
2. **都在选中日那一列断开**：拉开区顶部的线用两个伪元素分左右两段，断口位置按「列宽 = (100% - 6px)/7」结合 `--cal-col`（选中列序号）算；上面那条线则逐格画、选中格与补位格不画 ⇒ 到选中日那里自然断掉。
3. **线高 5px、离边 4px**（此前 1px / 3px，都太细太贴）。

**实现细节（下次照抄）**：grid 里没有「整行」容器 ⇒ 上面那条线只能**逐格画**（每格 `::before`，格间 1px 缝隙处会有 1px 的断口，与网格缝一致，观感自然）；拉开区是跨 7 列的整行元素，可以用两个伪元素精确断开。
