## 一、是什么

### 1.1 一句话

主界面顶部一级分段控件**第二个 tab「执行记录」**的整屏内容：查**所有任务**的执行流水账（`task_instances` 全表，跨任务），按时间倒序，以**天分组的时间轴**呈现。

### 1.2 与「执行记录」同名东西的区别（不许混）

| | 本页（总查询页） | 卡片展开区的「执行记录」面板 |
|---|---|---|
| 范围 | **全部任务**的流水 | **单个任务**的历史 |
| 入口 | 顶部一级 tab（任务配置 / 执行记录 / 调试） | 卡片展开 → 三面板之一 |
| 形态 | 时间轴（天分组 + 时间点块） | 表格（7 列，定高） |
| 文档 | 本文件 | [`task-expand-panels.md`](task-expand-panels.md) |
| 取数 | 同一端点 `GET /tasks/instances`（不传 `taskId`） | 同端点，传 `taskId` |

两者**共用同一条取数链路与同一套状态口径**，但形态与过滤各自独立，改一个不必动另一个。

### 1.3 现状与改动面

- 现有「执行记录」屏 = `src/client/index.ts` 三元里那个**最简测试版**分支（两个原生 select + 原生表格，数据来自调试快照、无分页）。✅ **2026-10-04 已整段删除**，由本页取代。
- 落码位置：视图 = `src/client/records-timeline.tsx`；`src/client/index.ts` 的 `tab === 'records'` 分支渲染它。
  ⚠️ 该分支**排在最外层 `data === undefined` 门槛之前** —— 新页走 HTTP，不再吃调试快照，否则快照缺失会把新页一起挡掉。
- 任务选择器 = `src/client/ui/TaskPicker.tsx`（全站唯一实现，见 [`../ui-foundation.md`](../ui-foundation.md) §5.4）。
- 服务端与取数层**零改动**：`GET /tasks/instances`（`src/index.ts:828`）当初即按「未来总查询页共用（决策 55）」设计；`store.listInstancesByQuery`（`src/store.ts:820`）**游标分页已实现**；客户端 `fetchInstances`（`src/client/query.ts:112`）已带回 `nextCursor`。
- 旧测试屏专用文案键（`recordsHint` / `filterStatus` / `filterTask` / `expandHint` / `debugInstancesEmpty` / `eventsOf` / `eventsEmpty` / `colSeq` / `colTs` / `colKind` / `colDetail` / `colTask` / `colSlot` / `colAttempt` / `colUpdated`）与 `basenameOf` 已一并删除；客户端调试快照类型也不再声明 `instances` / `events`（宿主协议未动）。

## 四、时间轴形态

### 4.1 分组与排序

| 项 | 口径 |
|---|---|
| 排序 | 服务端 `scheduled_at DESC, id DESC`（游标顺序）⇒ 客户端**不再重排**，按取回顺序渲染 |
| 天分组 | 以 `scheduled_at` 所在**日历日**为 key。落码时**优先直接在 `InstanceRow` 声明 `logical_date`**（服务端 `SELECT *` 已带回该列，零成本），避免客户端用本地时区再推一遍与服务端口径打架 |
| 天标签文案 | `2026 年 4 月 30 日`（中）/ 英文按 locale；右侧附**当天条数** |
| 天内顺序 | 同天内的块按取回顺序（即倒序：晚的在上） |
| 跨页合并 | 追加下一页时，**若首行落在已渲染的同一天 ⇒ 并入该天块，不得另起一个同名天标签** |
| 轴 | 天标签下方一条 1px 竖线（极浅描边 `--tdt-border-faint`）贯穿当天的块，建立「轴」的观感；块本身**不画圆点**（用户：天标签在最上面，朋友圈式） |

### 4.2 执行块（一个块 = 一次执行）

```
│ 03:05   每日镜像升级巡检                3 分钟 · 12.4k token
│         工作区 · 成功
```

| 区 | 内容 |
|---|---|
| **左缘色条** | 4px 宽，圆角与块一致，**颜色即成败**（见 §五） |
| 时间点 | `HH:mm`（**等宽数字** `tabular-nums` + 代码字体，与倒计时同款防跳动）；跨天只在天标签下显示，块内不重复日期 |
| 任务名 | 有编号时 `[编号] 名称`（与前置任务下拉同款）；过长走 `MarqueeText` |
| 次信息 | 工作区 · 状态文字 · 时长（`dispatched_at → finished_at`；无终态则显示「运行中」） |
| 悬浮 | 整块轻微蓝底（**底色只在 hover 时出现**，一屏几十条时不噪） |
| 点击 | 整块可点 ⇒ **打开会话**（见 §六） |

> ⚠️ 块内**不显示**计划时刻 `scheduled_at` 的完整串（日期已在天标签、时刻已在左）；实际派发时刻与计划时刻不一致（迟到补跑）时，才在次信息里补一句「计划 03:00」。

## 五、成败表达（用户点名：**不用图标**）

**唯一表达 = 块左缘那条 4px 色条**（外加状态文字，文字只作可读兜底）。**不许加成功勾 / 失败叉 / 转圈图标**——那是卡片表格的做法，时间轴上会变成一屏几十个图标，噪音。

| 状态 | 色条 | token |
|---|---|---|
| `succeeded` 成功 | 绿 | `--tdt-success` |
| `failed` 失败 | 红 | `--tdt-danger` |
| `skipped` 未执行（配置 / 前置不满足，**是正式终态**） | 黄 | `--tdt-warning` |
| `dispatched` / `running` 在跑 | 蓝，**缓慢脉动** | `--tdt-business` |
| `unknown`（重启孤儿） | 中性灰 | `--tdt-fg-3` |

- 脉动必须尊重 `prefers-reduced-motion`（同现有 `.dsh-tdt-rec-ic-run` 的处理）。
- 色条颜色**只消费 `ui/tokens.ts` 的 token**，不写字面量、不新增 `--tdt-*`。
- ⚠️ **与卡片状态灯「执行中 = 绿脉动」不冲突**：那里是状态灯表达「在跑」；这里是色条区分终态成败，蓝才不会与「成功绿」混淆。若用户要求与卡片同色，改这一行即可（单点）。

## 七、分页（用户拍板：**加载更多**，不做页码）

| 项 | 口径 |
|---|---|
| 方式 | **游标追加**：`fetchInstances({ …, cursor, limit })`，末行 `(scheduled_at, id)` 编码成 cursor（服务端已实现） |
| 首屏 | `limit = 50`（用户「20 或 50，具体再看」；取 50，落码真机看密度再调） |
| 默认时间档 | 最近 3 天（过滤行第 1 项） |
| 触发 | 滚到底自动续拉；同时在途去重（`loading` 期间不重复发请求），**不做预取** |
| 硬上限 | **2000 条**：到达即停止自动续拉，底部改显「已加载 2000 条，请缩小时间范围查看更早记录」 |
| 到底 | `nextCursor === null` ⇒ 底部显「没有更多了」 |
| 重置 | 任一过滤条件变化 ⇒ 清空列表 + 游标回第一页 |

**为什么不做页码**（详见 worklog §3.1）：① 服务端游标已实现，页码要新增总数统计；② 数据在动（看第 2 页时新执行进来了）⇒ 页码整体错位，游标锚定末行不受影响；③ 时间轴按天续接，翻页会把「某一天」从中间劈开。

**承载**：2000 个轻量节点（一行文字 + 一条色线）浏览器可承载，真正会卡的是几万节点叠复杂样式与动画；默认时间档 + 2000 上限两道保险即为此。

## 八、取数

| 项 | 口径 |
|---|---|
| 端点 | `GET {prefix}/tasks/instances`（`src/index.ts:828`） |
| 参数 | `workspace`（由服务端 `workspaceTaskIdsOf` 反查 task_id 集合，**不动表结构**）/ `status`（逗号分隔）/ `from` / `to`（半开区间）/ `taskId`（选中单个任务时）/ `cursor` / `limit` |
| 客户端 | `fetchInstances`（`src/client/query.ts:112`），返回 `{ rows, nextCursor }` |
| 数据真实性 | **全部真实取数**，禁止任何模拟 / 占位数据（仓库铁律） |
| 刷新 | 不做自动轮询（执行记录是历史账，不是实时面板）；靠切 tab 进来时重取 + 过滤变更重取。若真机发现「在看的时候跑完了看不到」，再议加轻量刷新 |

## 九、空态 / 加载 / 错误

| 态 | 呈现 |
|---|---|
| 首次加载 | 居中 loading（复用 UI 基础层 `Loading`） |
| 空结果 | 居中空态：无匹配记录（非「出错」），文案区分「本时间范围内没有执行记录」与「当前过滤条件下没有」 |
| 请求失败 | 错误文案 + 重试按钮；**不猜兜底数据、不清空已有列表** |
| 续拉中 | 底部一行小 loading，不遮挡已有内容 |
