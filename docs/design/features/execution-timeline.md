## 一、是什么

### 1.1 一句话

主界面顶部一级分段控件**第二个 tab「执行记录」**的整屏内容：查**所有任务**的执行流水账（`task_instances` 全表，跨任务），按时间倒序，以**天分组的流水账**呈现（日期小字行 + 一条条自带状态色浅底的独立块；2026-10-04 第三版起不再有外框与竖向时间轴）。

### 1.2 与「执行记录」同名东西的区别（不许混）

| | 本页（总查询页） | 卡片展开区的「执行记录」面板 |
|---|---|---|
| 范围 | **全部任务**的流水 | **单个任务**的历史 |
| 入口 | 顶部一级 tab（任务配置 / 执行记录 / 调试） | 卡片展开 → 三面板之一 |
| 形态 | 流水账（日期小字行 + 独立块，块可就地展开） | 表格（7 列，定高） |
| 文档 | 本文件 | [`task-expand-panels.md`](task-expand-panels.md) |
| 取数 | 同一端点 `GET /tasks/instances`（不传 `taskId`） | 同端点，传 `taskId` |

两者**共用同一条取数链路与同一套状态口径**，但形态与过滤各自独立，改一个不必动另一个。

### 1.3 现状与改动面

- 现有「执行记录」屏 = `src/client/index.ts` 三元里那个**最简测试版**分支（两个原生 select + 原生表格，数据来自调试快照、无分页）。✅ **2026-10-04 已整段删除**，由本页取代。
- 落码位置：视图 = `src/client/records-timeline.tsx`；`src/client/index.ts` 的 `tab === 'records'` 分支渲染它。
  ⚠️ 该分支**排在最外层 `data === undefined` 门槛之前** —— 新页走 HTTP，不再吃调试快照，否则快照缺失会把新页一起挡掉。
- 任务选择器 = `src/client/ui/TaskPicker.tsx`（全站唯一实现，见 [`../ui-foundation.md`](../ui-foundation.md) §5.4）。
- 服务端与取数层**零改动**：`GET /tasks/instances`（`src/index.ts:828`）当初即按「未来总查询页共用（决策 55）」设计；`store.listInstancesByQuery`（`src/store.ts:820`）**游标分页已实现**；客户端 `fetchInstances`（`src/client/query.ts:112`）已带回 `nextCursor`。
- 旧测试屏专用文案键（`recordsHint` / `filterStatus` / `filterTask` / `expandHint` / `debugInstancesEmpty` / `eventsOf` / `eventsEmpty` / `colSeq` / `colTs` / `colKind` / `colDetail` / `colTask` / `colSlot` / `colAttempt` / `colUpdated`）与 `basenameOf` 已一并删除；客户端调试快照类型也不再声明 `instances` / `events`（宿主协议未动）。

## 三、过滤行

一行，控件同高 md(28)。**版式照任务列表**（用户 2026-10-04 返工点名「过滤和界面参考任务列表」）：

```
[ 全部 | 成功 | 失败 | 进行中 ]        [时间范围] [工作区▾] [任务搜索选择器]
└─ 左：状态分段控件（与任务列表那排「全部/已开启/已关闭/异常」同位同款）    └─ 右：时间与其余过滤
```

| 侧 | 控件 | 形态 | 默认 | 说明 |
|---|---|---|---|---|
| **左** | **状态** | **分段控件 `Segmented` 四档**（全部 / 成功 / 失败 / 进行中），与任务列表顶部同款 | 全部（= 不过滤） | 档位成员走 `status-text.ts` 的 `statusesOfBucket`（`succeeded` / `failed`〔含 `skipped`〕/ `running`〔含 `pending`·`dispatched`·`running`·`unknown`〕）——**与卡片执行记录面板同一个桶**，文案 `statusTextOf`。⚠️ 这里**没有**状态下拉（2026-10-04 版式返工已删） |
| 右 | **时间范围** | 复用 UI 基础层 `TimeRange`（`src/client/ui/TimeRange.tsx`，day 精度） | **最近 3 天**（用户拍板「最近三四天」） | 边界一律走 `rangeToQuery`（半开区间 `[from, to)`），禁止各页面自己算 |
| 右 | **工作区** | 下拉（`SelectField`），定宽 180（与任务列表 `WS_WIDTH` 同宽） | 全部 | 值 = 工作区 `title`（服务端按 title 匹配）；候选来源见 §三.1 |
| 右 | **任务** | **带搜索的任务选择器 `TaskPicker`**（不是普通下拉） | 未选 = 不过滤 | 见 [`../ui-foundation.md`](../ui-foundation.md) §5.4；**受「工作区」作用域影响，实时联动**；改工作区时若已选任务不在新作用域 ⇒ 客户端清掉该选择（避免「工作区筛了 B、结果却是 A 的记录」） |

**改任一条件 ⇒ 重置游标与已加载列表，重新取第一页**（不保留旧结果拼接）。

## 四、版式：日期小字行 + 一条条独立块

> 2026-10-04 **第三版定稿**（用户原话「把外面整个框去了，不要框。然后前面的那个时间轴也去了，不要时间轴」）：
> **撤掉了**灰底圆角外框（`.dsh-tdt-rec-band`）与**贯穿竖轴**（含天节点圆点）。整页直接铺在宿主面板底上
> （页面容器 `background:'transparent'`，插件不设底），节奏靠下面这一条条自带底色的**独立块**建立。

### 4.1 分组与排序

| 项 | 口径 |
|---|---|
| 排序 | 服务端 `scheduled_at DESC, id DESC`（游标顺序）⇒ 客户端**不再重排**，按取回顺序渲染 |
| 天分组 | 以 `scheduled_at` 所在**本地日历日**为 key（**不用服务端 `logical_date`** —— 那是**任务时区**的日历日，而排序键与时间范围过滤都是 `scheduled_at`；分组键与排序键**同源**才不会把同一天劈成两个同名日期行） |
| 天内顺序 | 同天内按取回顺序（即倒序：晚的在上） |
| 跨页合并 | 追加下一页时，**若首行落在已渲染的同一天 ⇒ 并回该天，不得另起一个同名日期行** |

### 4.2 日期小字行

```
🕒 2026 年 10 月 30 日 · 星期五 · 8 条
```

| 项 | 口径 |
|---|---|
| 形态 | 一行**小字**：时钟图标 + 日期 + `·` + 星期 + `·` + 当天条数 |
| 字号 | `--tdt-font-md`(13px) / 500 字重；日期与星期 `--tdt-fg-2`，图标与条数 `--tdt-fg-3`（用户：字要小一点） |
| 图标 | 官方 `IconClockOutlineRegular`（⚠️ 官方 primitives **没有日历图标**，见 `primitives.d.ts` 的记载） |
| 星期 | `Intl.DateTimeFormat(localeTag, { weekday: 'long' })`，与日期格式化器一起**按语言记忆化**（不硬编码某种语言） |
| 条数 | 文案键 `recordsDayCount`（`{n}` 插值） |
| 吸顶 | ❌ **不吸顶**（2026-10-04 拍板）：撤掉外框后底下是宿主面板底，吸顶必须给不透明底色，怕与真实底色差出一条横带 |
| 间距 | 上 `--tdt-space-3`(12px)、下 `--tdt-space-2`(8px) |

### 4.3 条目（一条 = 一次执行）—— 块内**左右两列**（2026-10-04 第四版）

```
┌ 5px ┬──────────────────────────────────────────────┬───────────────────────────────┐
│     │ [012] 每日镜像升级巡检                         │ [⬜][⬜][+2]  [查看会话]  [⌄] │
│     │ 工作区A · 🕰计划 15:10 · 🕐实际 15:12 · ⟳时长 03:00 · 39.2K                    │
└─────┴──────────────────────────────────────────────┴───────────────────────────────┘
```

| 列 | 内容 |
|---|---|
| **左列**（`flex:1 1 auto; min-width:0`） | 第 1 行 = 名称；第 2 行 = 信息行（单行可省略）；块有 5px 竖条时左侧额外让位 |
| **右列**（`flex:none`，**单行控件组**，垂直居中） | 自左至右：产出物图标（≤3 + `+N`）→「查看会话」按钮（基础层 `Button` outline sm）→ 展开箭头（**基础层 `IconButton`**，plain + sm = 24×24，与任务配置卡片那一枚**同一份实现**：同尺寸、同 hover 底色、展开时 `rotate(180deg)`、拦冒泡、不挂 `title` 只留无障碍名） |

| 行 | 区 | 内容 |
|---|---|---|
| 1 | 名称 | 有编号时 `[编号] 名称`（`--tdt-font-lg`/600）；过长走 `MarqueeText`（跑马灯唯一抽象）；查不到任务（已删）时**原样显示 `task_id`**（不编造） |
| 2 | 工作区 | 任务表（`overview`）按 `task_id` 反查；任务已删 ⇒ 退回**派发快照** `workspacePath` 末段（当次执行当时的值）；都没有 ⇒ 该段不显示（**不编造**） |
| 2 | 计划 / 实际 / 时长 | **各带 12px 小图标**（2026-10-04 第五轮统一：计划 = 官方闹钟 `IconAlarmClockOutlineRegular`、实际 = 官方时钟 `IconClockOutlineRegular`、时长 = 官方队列 `IconQueueOutlineRegular`；⚠️ 官方**没有**日历 / 历史 / 沙漏，见 `primitives.d.ts` 全量 39 枚）；`时长` = `dispatched_at ?? scheduled_at → finished_at`（与卡片面板同口径） |
| 2 | Token | `token_in + token_out`（为 0 不显示），**迁到信息行末尾**（2026-10-04 第四版：不再放右下角），悬停看 `输入 / 输出 / 缓存` 明细 |
| — | **信息行排版** | **固定单行**（`white-space:nowrap`）+ **溢出省略号**（用户：「多出的部分显示成 ...」）；段与段之间的 `·` 由 CSS `::before` 自动补，不手写分隔节点；段内图标与文字 4px 间距 |
| 3 | 备注 | 仅失败 / 未执行有原因时出现：`备注：…` 单行省略、悬停看全文（`--tdt-fg-3`，**不标红**）；跨整块宽度（用户 2026-10-04 明确要保留：「我执行错了就是要看备注」） |

## 七、分页（用户拍板：**加载更多**，不做页码）

| 项 | 口径 |
|---|---|
| 方式 | **游标追加**：`fetchInstances({ …, cursor, limit })`，末行 `(scheduled_at, id)` 编码成 cursor（服务端已实现） |
| 首屏 | `limit = 50`（用户「20 或 50，具体再看」；取 50，落码真机看密度再调） |
| 默认时间档 | 最近 3 天（过滤行第 1 项） |
| 触发 | 滚到底自动续拉（`IntersectionObserver` 观察列表末尾哨兵，**观察者只建一次**、最新逻辑走 ref）；同时在途去重；**不做预取**（无 `rootMargin`）。底部另给「加载更多」按钮作兜底（`IntersectionObserver` 不可用 / 想手动续拉时） |
| 硬上限 | **2000 条**：到达即停止**续拉**，底部改显「已加载 2000 条，请缩小时间范围查看更早记录」。⚠️ 上限**只拦续拉**，首屏永远允许取 ⇒ 满额后改过滤条件不会白屏（2026-10-04 评审修正） |
| 到底 | `nextCursor === null` ⇒ 底部显「没有更多了」（**优先于上限提示**） |
| 失败 | 续拉失败 ⇒ 底部红色「执行记录加载失败：<原因>」+「重试」按钮，并**暂停自动续拉**（否则哨兵会把失败重试刷成风暴）；已有列表**不清空、不置空态** |
| 重置 | 任一过滤条件变化 ⇒ 清空列表 + 游标回第一页（**首屏不受上限限制**） |

**为什么不做页码**（详见 worklog §3.1）：① 服务端游标已实现，页码要新增总数统计；② 数据在动（看第 2 页时新执行进来了）⇒ 页码整体错位，游标锚定末行不受影响；③ 流水账按天续接，翻页会把「某一天」从中间劈开。

**承载**：2000 个轻量节点（一行文字 + 一条色线）浏览器可承载，真正会卡的是几万节点叠复杂样式与动画；默认时间档 + 2000 上限两道保险即为此。
