# 任务日程（月历视图）

> **状态**：🔵 落码（2026-10-05 首版，冒烟 639/0，真机待验）
> **来源**：用户 2026-10-05 需求原话 —— 「希望做一个像日历一样的界面，用来展示任务的执行情况。比如，我能查到去年某一天执行了哪些任务；也能查到未来（比如明年 10 月 1 号）计划执行哪些任务……以一个月为维度，把这个月的日历显示出来。在日历上标记出我执行成功的、执行失败的、即将执行的，或者跳过的，把这些都填到日历里面去。」
> **拍板**：① **新增独立第四个一级 tab「任务日程」**（不塞进「执行记录」里做视图切换）；② 未来计划**只算已启用的任务**；③ 过滤照常给（工作区 / 任务 / 状态），**日期维度不用时间范围控件**，改成月份翻页（一页 = 一个自然月）；④ 月份可自由翻到任意过去月与未来月，翻到哪算到哪。
> **配套**：[execution-timeline.md](execution-timeline.md)（相邻的另一页：流水账，按天分组倒序）、[../data-model.md](../data-model.md)（实例行与排期字段）、[../../worklog/task-calendar.md](../../worklog/task-calendar.md)（过程）

对应页面：`src/client/task-calendar.tsx`（`src/client/index.ts` 的 `calendar` 分支）；纯计算核 `src/calendar-plan.ts`；数据通道 `src/client/query.ts` 的 `fetchInstancesLite`。

## 一、它是什么、不是什么

| | 任务日程（本页） | 执行记录（流水账页） |
|---|---|---|
| 看的角度 | **日历**：一页一个自然月，按天铺开 | **流水**：按时间倒序铺开 |
| 时间范围 | 由**月份翻页**决定（一页 = 整月） | 由**时间范围控件**决定 |
| 含未来 | **含**（按当前定义推算的计划刻度） | 不含（只查已落库的行） |
| 分页 | 不分页，整月一次取满；触及上限给截断提示 | 游标分页，首屏 50、上限 2000 |
| 边界 | 与「任务展开三面板」里的单任务执行记录无关 | 同左 |

⚠️ 与调度器是**两个方向**：调度器（Loop A）到点才建行、**不预建未来行**（决策 31 懒建行）。所以本页的未来格子是「按现在的任务配置推算出来的计划」，**不是**「已排定的执行」—— 见 §三。

## 二、页面规格（2026-10-06 交互改造后）

1. **顶部只有一行**：左 = 月份导航（上月 / 月份标题 / 下月 / 今天）；**右 = 两态图例 + 本月条数 → 工作区下拉 → 任务选择器**（三者与月份导航**同一行、居右对齐**）。⚠️ **没有状态分段过滤**（用户 2026-10-06：全部 / 成功 / 失败 / 运行中「没有意义」），也没有时间范围控件（日期维度 = 月份翻页）。
2. **月历网格**：周一为首 7 列 × 6 行（网格走 UI 基础层的 `buildMonthCells`，与日期框的自绘日历**同一份实现**）。**每格是一张独立卡片**（1px 描边 + 微圆角 + 6px 间隔）—— 用户 2026-10-06「每一格一定要有线」，连片网格在暗色下会糊成一片；参考主流日历（Google / Apple / Notion 月视图）取卡片式。格子**定宽定高**（`height` 固定，不随当天条目数变）。
   - **格内条目 = 方形小标签**（不是圆点）：标签前 3px 状态色竖线 + 同色系浅底 + 时刻；时刻位数固定 ⇒ 标签宽度固定。
   - **一格 3 列 × 3 行 = 9 个位子**：前 8 位放时刻，第 9 位放 `…N`（N = 还剩几条，点它 = 拉开当天看全部）。任务名与状态留给悬停说明。
   - 今天 = 品牌色圆底数字；非本月的补位格淡化、**不放数据**、不可点。
3. **点某天 = 那一天所在的那一周像手风琴一样拉开**（跨 7 列的面板插在该周下面），当天的执行信息全部铺在拉开区里：
   - **已发生**的每条 = 执行记录页**那同一套** `RecordItem`（不另写一份）：点它**可再展开** ⇒ 前置任务、产出物、执行日志（事件流水）都在里面；
   - **计划（「预计执行」）= 与已发生共用同一个 `RecordItem` 的虚线块**（2026-10-06 r14 起，不再是"一行虚线行"）——规格见 §三；
   - **有多少条显示多少条**，拉开区**不设内部滚动条**（要滚就滚页面）。
   - 同一天再点一次 = 收起。
   - 拉开有 **180ms 的展开动画**（不能「啪」一下弹出来）。
   - **展开的指示 = 两条 4px 蓝色胶囊线**（用户 2026-10-06 r10）：① **点开的那一格自己顶部**一条（离边 4px），**其余格子保持原样、不加线**；② 拉开区**顶部**一条，左右两端内缩 4px、**中间在选中格那一列断开，且断口端点必须正对该格的左右边缘**（不留额外间距）；③ 线 = `--tdt-business` 蓝、高 4px、两端全圆。
   - **选中格与拉开区的底色 = `--tdt-selected-bg`**（token 层，`ui/tokens.ts`，2026-10-06）：**两个主题方向不同** —— 浅色 = 掺 12% 文字色（⇒ 比本月格**深一档**）；深色 = 掺 12% 背景色（⇒ 比本月格**暗一档**，但远不到背景的黑）。⚠️ 深色下不能掺文字色（那是白 ⇒ 选中反而比本月浅）。
   - 深色主题的四层亮度（用户定的 1 > 4 > 3 > 2，从深到浅）：页面背景 > 选中格/拉开区 > 本月可选日期 > 相邻月补位格。
   - ⚠️ 别用 `--tdt-plate` / `--tdt-surface-2` 做选中态：它们与常态底色太接近，**看不出变化**（r11 的教训）；别用蓝（open-bg 系在这里显灰）；不许叠半透明（会把格内状态色带脏）。
   - **深色主题下的四层亮度**（用户 2026-10-06 定的顺序 1 > 4 > 3 > 2，从深到浅）：① 页面背景（最深）→ ④ 选中格 / 拉开区 → ③ 本月可选日期 → ② 相邻月补位格（最浅）。
   - 线在**格子底部**（`::after`，离边 4px、高 4px、两端全圆）；拉开区顶部另有同款一条（在选中列断开、断口正对该格左右边）。内容一律从**左上角**排（上内边距 6px），不为线让位。
   - **拉开区里的计划条目 =「预计执行」虚线块**（2026-10-06 r14，用户拍板「不是保持统一，是用同一个东西」）：**复用已发生那同一个 `RecordItem`**（传 `planned` 模式），**禁止另写第二份计划专用块**。仅以下几点与已执行不同：① 虚线蓝边块（运行 = 实底蓝「正在跑」，预计 = 虚线蓝「将要跑」，同色系区分）；② 状态标签「预计执行」（虚线描边、透明底）；③ 实际执行 = 「未执行」、时长 = 「--」、Token = 「--」（没有真值就占位，不编造）；④ 前置 1、2 / 工作空间 / 计划时间照常显示，前置取**任务定义** `depends_on`（没有快照可读），名字可点进查看档；⑤ 右侧照常有展开 ⇒ 展开看前置任务清单。

交互与降级：

- 翻月 / 改过滤 ⇒ 重新取数；请求序号作废旧响应（与执行记录页同一条规矩）。
- 拉开区里展开某条时**才**按会话 id 补拉全量行（取 `snapshot`：前置 / 产出靠它）与 `fetchEvents`（事件流水）；格子与拉开区的第一次展示不发起请求（整月行已在内存）。
- 单月记录超过上限 ⇒ 顶部明确提示「已截断，请用过滤缩小范围」，**不静默丢**。
- Loading 走页面右下角统一的那一个（不新建第二个加载指示）。
- 任务名取任务定义的真实 `title`，取不到给 `id` —— **不编造名字**。

## 三、两态：已发生 vs 计划（硬要求）

| | **已发生** | **计划** |
|---|---|---|
| 来源 | `task_instances` 的真实行 | 浏览器内用 `planEntriesByDay` 现算 |
| 有没有状态 | 有（成功 / 失败 / 跳过 / 运行中 / 未知） | **没有**（还没发生） |
| 画法 | 格内：状态色**实心**小点 + 状态色浅底；拉开区：执行记录页**同一套** `RecordItem` | 格内：同色系**虚线空心**点；拉开区：**同一个 `RecordItem` 的「预计执行」虚线块**（2026-10-06 r14） |
| 悬停 | 时刻 + 任务名 + 状态名 | 「按当前任务配置推算的计划，尚未产生执行记录」 |

为什么必须分得清：未来**没有实例行**（决策 31），日历上的未来格子是**按当前定义现算的推算值** —— 任务改排期 / 停用后它会跟着变。这是**真实计算、不是模拟数据**（仓库硬规则：正常功能一律真实取数，禁止模拟），但它是「计划」而不是「事实」⇒ UI 与文案（图例、悬停、`calPlanHint`）都要如实说明。

**计划的三条硬规矩**（在 `src/calendar-plan.ts` 里实现，冒烟有断言）：

1. **只算 `enabled` 的任务**（用户拍板）：停用任务不会跑，给它出格子就是撒谎。
2. **只列 >= now 的刻度**：过去「该跑没跑」的日子，日历上只能显示真实记录（没有就是没有）；拿**现在的定义**回填过去会造出从未发生过的执行。
3. **`once` 出窗口即作废**（决策 18 / 拍板 A）：过期的 `once` 不算计划（同 ②，只认 >= now）。

**状态过滤与计划的关系**（2026-10-06 起该问题不存在）：页面**没有状态过滤**（用户拍板去掉了）⇒ 历史与计划始终同显，格子与拉开区看到的都是「那天全部有什么」。

## 四、取数（三条来源，两条 HTTP + 一条现算）

| 数据 | 来源 | 说明 |
|---|---|---|
| 任务定义（排期 / 启用 / 名称） | 面板已有的 `useTaskOverview()`（`/tasks/overview`） | 与任务列表**同一份轮询数据**，不额外拉，口径不会两处不一致 |
| 已发生的历史 | `GET /tasks/instances?light=1`（`fetchInstancesLite`） | 见 §4.1 |
| 未来计划 | 浏览器内 `planEntriesByDay`（`src/calendar-plan.ts`） | 见 §4.2 |

### 4.1 历史为什么走 `light=1`（本功能唯一的服务端改动）

- 实例行带 `snapshot` 列（派发快照：提示词 / 附件 / 依赖的 JSON，单行 1.5–4 KB）；日历要一次拿满整月（几百到上千行）⇒ 走全量行一次就是数 MB。
- **决策**：复用既有路由加 `light=1` ⇒ 行**剔除 `snapshot`**（约 200 B/行）、**不做 `session_title` 富化**（那要逐行 `JSON.parse(snapshot)`）、上限放宽到 **3000**、不分页；触及上限回 `truncated: true`。
- 过滤条件与全量查询**同一套**（`store.instanceWhere` 抽出共用）⇒ SQL 条件不写第二遍；既有 `listInstancesByQuery` 的 500 上限与游标语义**一个字都没改**（记录页分页依赖它）。
- 任务名由客户端从任务定义本地映射，失败 / 跳过的原因（`note`）**照旧带回**（`attachNotes` 只对终态行做一次 IN 查询）。
- 拉开区里**展开某条**时，按会话 id 走既有 `fetchInstanceBySession` 补一次**全量行**（只为拿 `snapshot`：前置 / 产出 / 附件路径在里面），并 `fetchEvents` 取事件流水。没有会话 id = 压根没派发（如 skipped）⇒ 本来就没有前置 / 产出，不补、也不假装有。

### 4.2 未来为什么在浏览器里现算

- `src/schedule-next.ts` 已于 2026-10-05 抽成**服务端与客户端同一份**的纯计算核（唯一外部依赖 `cron-parser`，由 tsdown 内联进 client bundle）⇒ 客户端能直接算，**不需要新接口**，也不许另写一份 cron 解析。
- **按自然周分片调用** `scheduledSlotsFor`：`cap` 是**单次调用**的迭代上限，每分钟档整月约 44640 个刻度，整月一次算会被**静默截断**（表现为「月底那几天的任务凭空消失」）。分片是半开区间 `[start, end)` ⇒ 不重不漏；一周最多 10080 个刻度，远在 cap 之内。冒烟有「每分钟档整月 23760 条」的反向断言守着。
- 一次性任务走 `onceScheduledAt`（整月只判它那一天）。

## 五、分桶与状态口径（与既有页一致，不许各写一份）

- **按「浏览器本地日」分桶**：与执行记录页同一抉择（`scheduled_at` 的本地日；`logical_date` 是任务时区日，只声明备查）。实现上复用 `logicalDateOf`（`schedule-next.ts`），**不新写日期格式化**。
- **月区间半开** `[月首 00:00, 次月首 00:00)`：`monthRangeOf` / `monthRangeQuery`，与 `ui/time-range.ts` 的 `rangeToQuery` 及 `store.ts` 的 `scheduled_at < toTs` 同一条规矩。
- **状态名与色调**一律走 `status-text.ts` 单源（`statusTextOf` / `statusToneOf` / `statusesOfBucket`），日历里不新写映射。
- **月历网格**走 `ui/DateTime.tsx` 的 `buildMonthCells`（2026-10-05 上提为导出，与日期框的自绘日历共用），周表头与月份标题走 `calendarLabelsOf` 单源。

## 六、边界（本版不做）

- 不做拖拽改期 / 手动加日程：日历是**只读视图**，改排期走任务编辑器。
- 不做年视图 / 周视图：只有月视图。
- **点格子里那个时刻弹右侧栏**看该次执行的详情 —— 用户 2026-10-06 提出后当场搁置（「执行记录现在没有右边弹出的东西」）：当前点时刻 = 拉开当天，要看详情在拉开区里展开那一条。等右侧栏支持「单次执行」再议。
- 计划**不预测依赖阻塞与窗口**：只算排期刻度，不预判「到那天会不会因为前置未达标 / 超窗而跳过」。
- 计划不进任何统计口径（它不是一个状态）。
- 调试页不随本轮改动（用户第一块需求「重构调试界面」另立工作包）。
