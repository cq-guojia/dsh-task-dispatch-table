## 一、是什么

顶部一级 tab「设置」的整页，**两块**：

| 块 | 干什么 |
|---|---|
| **插件设置** | 配置编辑的**正式主场**（表单 + 每项状态机 + 校验） |
| **插件日志** | 查 `plugin_log`（**插件进程**日志，不是任务日志）——自动刷新 / 手动刷新 / 显示 N 条 |

页面文件：`src/client/settings-page.tsx`（容器）+ `settings-config-block.tsx` + `settings-log-block.tsx` + `db-table.tsx` + `settings-data.ts`；服务端取数走 `/config`（读配置 / 写配置）与 `/db-query`（查表）。

## 二、插件设置（业务规则）

### 2.1 字段（7 项，一行两个）

| 字段 | 单位 | 说明 |
|---|---|---|
| 循环间隔 `tickMs` | 秒 | 调度器多久巡检一次任务表 |
| 运行日志保留 `logRetentionDays` | 天 | 清 `task_log` + `plugin_log` |
| 临时附件保留 `attachmentTmpRetentionDays` | 天 | 清上传临时区的孤儿副本 |
| 默认模型 `defaultProvider` + `defaultModel` | — | **一行连栏**：先选供应商、再选具体模型（同一项，一起算自定义 / 一起恢复默认） |
| 派发宽限 `dispatchGraceMs` | 秒 | 派发后等会话启动的最长时间 |
| 运行租约 `leaseMs` | 秒 | 运行中多久**没有动静**才回收占用（正常在跑会被不断续期，不会被掐断） |
| 观察宽限 `unknownGraceMs` | 秒 | 会话状态未知时再观察多久 |

- **不暴露路径类**（`statePath` / `tasksDir`）：「插件装到哪儿」不该让用户填（用户 2026-10-08）。
- 每项 = 标题 + 右侧「?」详细说明（悬停气泡）+ 输入框 + 一句短说明（默认宽度一行写得下）。
- 数字框**只吃数字**（非数字字符在输入时滤掉），**不用原生 `type="number"`**（基础层守卫禁止原生 spinner）。

### 2.2 每项的「自定义 / 恢复默认」状态机（照抄 `dsh-session-title-pattern`）

- 值 **≠ 系统默认值** ⇒ 标题右侧出现「自定义」徽章 + 「恢复默认」按钮；
- 值 **= 系统默认值** ⇒ **两个都不显示**（不是灰着，是整个不出现）；
- 「恢复默认」把该字段（连栏项则两个一起）退回 `CONFIG_DEFAULTS`。

### 2.3 保存与校验

- **没有任何改动 ⇒ 保存按钮灰着**（disabled）。
- 点保存**先本地校验**：一次把**所有**问题查出来（数字看范围、连栏看「选了一个必须选另一个」），出问题的框**描红**（改好即退），并弹**一次** `FloatingToast` 列出全部问题。
- 提示**一律走统一 Toast**（与新增 / 修改任务同款），不在表单里挂错误文字。
- 后端机读错误码**必须翻成人话**再弹（`update-failed` / `too-small-*` / `invalid-*` / `empty-patch` → 中文整句），**不许把机读串甩给用户**。

### 2.4 配置存哪（关键口径）

- **存自有状态库**：`state.db` 的 `meta` 表 `pluginConfig` 键（JSON 对象），与任务表 `tasksInline` 同一条通道。
- **生效值优先级**：`程序默认值（CONFIG_DEFAULTS）` < `宿主基线配置（entry config / patch yml）` < `数据库（用户改过的那层）`。库里没有的字段 ⇒ 就是默认值。
- **等于默认值的字段不落库** ⇒ 改回默认值 = 撤销这条设置（库保持干净）。
- 保存后**即时生效**（更新运行态 + 广播 `CONFIG_CHANGED` + `tickMs` 变了重启定时器），不需要重启。
- ⚠️ **不写宿主的配置面**：宿主 `settings.update` 要求 Config schema 里有 volatile 字段（本插件全静态字段），其内部落盘用的 `configEditor` 也不是插件接口 —— 出处与详情见 [external/dsh-capabilities.md](../external/dsh-capabilities.md)「settings 写路径」条。
- 代价（已知）：宿主那个通用「插件配置」页面不显示这里的值（它读宿主自己的配置文档）；本页与插件详情页的 `config-panel` 都走我们自己的 `/config`，正常。

## 三、插件日志

- **控件排布（全插件统一）**：`自动刷新`（**默认勾选**）→ `刷新` → `显示 N 条`（**最右**，`显示 <下拉> 条` 与「任务配置 → 执行记录」同款）。
- 自动刷新 = 固定 5s 轮询；关掉开关或离开页面即停。不接 SSE（用户明确选择）。
- **列表照执行记录皮肤**（斑马纹 + hover + 同度量格子），但**表头不吸顶**：这里是页面滚动，吸顶会让表头浮在上下文之外、上面还漏内容 ⇒ 表头跟着内容一起滚走。
- `level` 列按语义着色：**info 不着色 / warn 黄 / error 红**。
- 列宽：`ts` 缩短成 `MM-DD HH:mm:ss` 并**定宽**，省下的宽度全给 `message`（正文可能很长，整段换行不截断）。
- 不再有内部滚动槽（2026-10-08 用户拍板：数据查询块删除后，日志直接让**页面**往下滚）。

## 四、边界（明确不做什么）

- **不做「数据查询」块**（原查 6 张表 + 筛选）：2026-10-08 用户拍板「整个砍掉，没有意义」，页面与服务端相关功能一并删除。
- **不做执行历史清理**：执行历史**永久保留**（`historyRetentionDays` 与 `purgeHistory` 已删除），设置页不给这个开关。
- **不做 SSE 订阅**看日志（轮询够用、且用户不想被持续推送打扰）。
- 宿主插件详情页的 `config-panel`（`plugins.bundle.config` 槽）保留作**旧入口 / 兜底**，暂不退役（用户「先不管」）。
