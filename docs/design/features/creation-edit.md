## 一、双循环（既有结论，不改）

| 项 | 口径 |
|---|---|
| Loop A（判定） | 只判「用户录入的这些任务此刻该不该跑」：刻度 + 窗口 + `enabled` + 前置任务是否完成 + 工作区是否存在。**不回看、不补跑**（决策 31 不变）——迟到的刻度错过就是错过，只记 `startup_missed` |
| 落库 | 判定通过 ⇒ 连同**派发快照**以 `dispatched` 落库，落库即止（不发动会话）；判定不过 ⇒ **不建行**，只记 `task_log` |
| Loop B（执行） | 只循环待执行记录表：发动 / 追问 / 重试 / 回收。**只读快照、不重判依赖** |
| 快照内容 | 当前任务配置 + 上游是被哪条实例放行的（task / instanceId / sessionId / 上游产出），全部冻结进库（决策 41/42/43 已落码） |

## 二、任务身份

| 字段 | 口径 |
|---|---|
| `id` | **系统生成的 UUID**，任务的唯一机器身份。保存闸门（决策 30）不变：无 id 补 UUID = 新增；带 UUID 必须命中现有表 = 修改；非 UUID 或 UUID 不在表内 ⇒ 整批 422 拒 |
| `title`（任务名称） | 人读，随时可改，**不参与身份** |
| `code`（任务编号） | 人读，只记录、**不做唯一性判断** |

## 三、保存 = 快照（本轮新增的核心动作）

**每次点保存，同时产出两样东西**：

| 产物 | 干什么用 | 粒度 |
|---|---|---|
| ① **整份配置快照** | 用户**改坏了能回滚**（排期 / 工作区 / 模型 / 提示词 / 附件清单全在里面） | 整份任务定义 |
| ② **提示词版本** | 提示词的细粒度版本与回滚 | 只提示词正文 |

**与「派发快照」的区别（两回事，都要）**：

| | 谁产生 | 什么时候 | 回答什么问题 |
|---|---|---|---|
| 保存快照（本文件 ①②） | 用户 | 点保存时 | 「我改坏了，能不能回去」 |
| 派发快照（决策 41，已有） | 程序 | Loop A 落库时 | 「这一趟到底跑的是哪一版配置」 |

> 派发快照是**程序执行链**，必须严格落库、可追溯；保存快照是**给人兜底的操作便利**。

**留档判定**：整份配置快照 = **内容变了才留**（与提示词版本同款判定）——连点保存不会刷出一堆一模一样的快照。
**保留策略与版本一致：不自动删**；管理入口（选 / 删）**本轮不做**（UI 已封档），先只落盘。

### 回滚语义

- 回滚分两档，让用户选：**只恢复提示词** / **恢复整个任务的设置**。
- 恢复整个设置时，快照里的**附件若已不在盘上** ⇒ **不拦保存**，只提示「以下 N 个附件已不存在，需重新上传」。理由：拦住会导致附件一丢就**连改排期、改提示词都改不了**；缺失由执行期兜住（§五 第 4 条 ⇒ 不执行 + 记 error）。
- 回滚**不影响在飞实例**（决策 41：在飞实例按派发快照走）。

## 四、提示词版本

| 项 | 口径 |
|---|---|
| 存储 | **文件系统，不进数据库**。`tasks/<task_uuid>/prompt-versions/<时间戳>.md`，一个版本一个文件；**读目录 = 版本列表**（文件名排序即时间序），读文件 = 内容 |
| 文件命名 | **纯时间戳**（如 `20260930T101530123.md`，精确到毫秒，字典序 = 时间序）。**不加 `v0001` 这类自增前缀**——不为此多写一套序号维护程序 |
| 触发 | **保存任务时**判定：当前提示词与「该任务最新版本文件内容」**不同** ⇒ 新建一版；相同 ⇒ 不建（改回旧内容也算不同，照建新版） |
| 比较口径 | 去**首尾空白**后比较 ⇒ 只按了个回车 / 末尾多了个空格**不算**改动 |
| 首次 | 新建任务首次保存 ⇒ **无条件建第一版**（否则没有基线，回滚无对象） |
| 版本备注 | 若填了，存同名 `<时间戳>.note` 纯文本；没填就没有这个文件 |
| 保留策略 | **不自动删**，一直留着。由用户在版本面板里自己选、自己删（删多删少是用户的事） |
| 回滚 | 用户在版本面板选一版 ⇒ 覆盖当前提示词（草稿层），用户再点保存才真正生效 |

## 五、附加文件

### 1. 目录结构（每任务一个自己的文件夹）

```
<插件数据根>/                        # = state.db 所在目录（resolveStatePath 的 dirname）
  tasks/<task_uuid>/                 # 任务目录，目录名 = 纯 UUID（title/code 可改，不能用来做目录名）
    prompt-versions/<时间戳>.md
    snapshots/<时间戳>.json          # 整份配置快照
    attachments/<原始文件名>
  task-attachments-tmp/              # 临时区（上传先落这里）
```

### 2. 上传 → 保存的搬移流程

1. **上传时**：文件先进临时区 `task-attachments-tmp/`，只在草稿层记录（此时任务可能还没建、没有自己的文件夹）。
2. **保存时**（确定要存了）才搬进 `tasks/<id>/attachments/`。
3. **修改已有任务**：把这次从列表里**移除**的附件**直接删掉**（磁盘上真删），把临时区里**新增**的搬进来。
4. 已在任务目录里的**未移除**附件：原地不动，不重复搬。

> 为什么真删：文件可能不小，用户不一定会自己清理；用户移除 + 保存 = 明确表态不要了。**不做附件版本管理，不留历史副本**（用户本机自己有）。

### 3. 命名

**保留上传时的原始文件名**（用户要自己看得懂，改成 UID 没法管）；同名冲突加序号后缀（`报告 2.md`）。文件名需 sanitize（`/ \ :` 与控制字符）。

### 4. 执行期校验（两次，都要查文件还在不在）

| 时机 | 行为 |
|---|---|
| Loop A 判定（准备派发） | 附件缺失 ⇒ 记 `task_log` |
| Loop B 发动前（真正执行） | 附件缺失 ⇒ **不执行**，记 error |

**附件缺失不判 `failed`、不吃重试额度**——重试也不会自己长出来。缺失既可能是上传型（任务目录下的文件被删），也可能是**链接型**（工作区内已有文件被删），两类同样判。

### 5. 清理

临时区 `task-attachments-tmp/`：**每天一次，删 3 天前的文件**（挂在既有 tick 里，跨天才干活：一个「上次清理日期」内存变量 + 一次删除；平时一轮只多一次日期比较，无持续负载）。

### 6. 删除任务

**当前没有删除任务的功能**。后续加按钮 + 二次确认；删除时**整个任务目录一起删**（附件 + 版本 + 快照）。规模约束沿用现状：单文件 20MB 上限、扩展名白名单。

## 六、前置任务

| 项 | 口径 |
|---|---|
| 可选范围 | 任务表里**所有任务都能选**——不论上次成功 / 失败 / 根本没启用。典型用法：先把整条链都入库，再统一开启 |
| 状态展示 | 下拉里用 icon 标出哪些是激活、哪些是关闭（已按此落码，决策 47：停用项标「（已停用）」） |
| 分界 | **设置是设置，运行是运行**：上游停用照样能选、能保存，只是跑不起来 |
| `dep_disabled`（新增） | Loop A 判定发现上游 `enabled=false` ⇒ 记 `task_log`，kind = **`dep_disabled`**（level warn），与「上游还没成功」的 `dep_blocked` 分开 ⇒ 日后能分清「还没跑成」和「永远不会跑」。**只是多一种 kind 取值，不动表结构、不动任务定义** |
| 列表页「上次判定结论」 | **先不加字段**：`task_log` 里已有全部数据，列表页按 task_id 取最新一条即可。等列表页真做时查询太重，再落 `last_verdict`（kind + ts + 原因） |

> **未来时刻实时算，历史结论查日志**：「下次预计执行时间」配置随时会改 ⇒ 只能实时算，不落库；「上次为什么没跑」是历史事件 ⇒ 查日志。

## 七-B、界面形态（右侧**占布局的分栏**，2026-10-01 拍板，U21）

> 取代 2026-09-28/29 定的「右侧贴边浮层 + 半透明遮罩」。过程见 [`worklog/editor-split-pane.md`](../../worklog/editor-split-pane.md)。

| 项 | 口径 |
|---|---|
| 形态 | **分栏**（与 U11 预览 dock 同一套：根容器的 flex 成员，`sticky + 100vh + flex:0 0 auto`，宽度走 `--dsh-tdt-editor-w`）；**主窗口被推窄而不是被盖住**，不再有遮罩、不再压暗页面 |
| 为什么改 | ① 原形态在主窗口旁点「编辑 / 新建」会把主窗口整页盖住，特别不方便；② 此前不敢做分栏是怕与文件预览的分栏重合 ⇒ 这个界面是**编辑态**，不会去开文件预览，不会重合（用户 2026-10-01） |
| 两条分栏同开 | 允许并存（编辑 + 预览各占一列，主窗口在中间）；**不互斥、不强收起** |
| 宽度 | 最小 / 默认 **520**（用户 2026-10-02 定：560 偏宽 → 试 500 → 试 530 → 定 520）；上限 = 视口 − 主面板最小宽(**760**) − 另一条分栏已占宽度 ⇒ **两条同时开着也要保住主窗口**（用户 2026-10-01 Q3）；可拖左缘调宽、宽度持久化（`dsh-tdt-editor-width`） |
| 关闭 | **没有遮罩** ⇒ 关闭路径只有「✕ / Esc / 取消」三条（原「点遮罩空白关闭」随遮罩取消）；改过内容时仍先弹脏判定确认 |
| 会话弹窗 | 「查看会话」全屏弹窗右侧让位 = 预览宽 + 编辑宽 ⇒ 不遮盖任何一条分栏（用户 2026-10-01 Q4） |
| 执行记录 | **不在这个界面里**：头部「基本信息 / 执行记录」切换删除，编辑/新建界面只管表单；执行记录归主面板自己的 tab |
| 提示词下三下拉（工作区 / 权限 / 模型） | **全部定宽**：以权限框为基准 **120px**，工作区 / 模型 = 1.5 倍 **180px**（用户 2026-10-02）。不再按选项文字自适应——那样换一个选项宽度就变一下（先各自撑到上限、三个都长才开始挤），观感一直在跳；显示不下就省略号（工作区 hover 跑马灯可读全名）。**空间不够时整体等比收缩**，但仍与选项长短无关 |
