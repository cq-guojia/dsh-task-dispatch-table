## 一、问题陈述

两个场景，同一个问题——「文件出现之后，用户怎么打开它」：

1. **会话弹窗内的文件引用**（已发生）：归档会话弹窗里，工具卡（读文件 / 写入 / 编辑）与对话内容中出现大量文件路径，当前是**纯文本不可点**。用户想看一眼「agent 写的那个文件长什么样」，没有入口。
2. **任务产出物的展示**（预告，v1.1 UI 的前置设计）：设置页 / 任务页要看**任务产出物**——每个会话的产出、每个任务实例的 `outputs` 清单。用什么形态展示、点击后怎么打开，与场景 1 是同一个动词问题。

## 二、待决问题（讨论时逐条拍板）

| # | 问题 | 候选方向（未定，仅列全） |
|---|---|---|
| Q1 | **打开动词**：点一个文件路径，执行什么动作？ | 宿主内预览（弹窗/抽屉）· 系统默认应用（shell open）· VS Code / 用户编辑器 · 复制路径（最保守） |
| Q2 | **宿主有没有现成能力**（源码核实，勿猜） | 官方 ui 包里有没有「打开文件 / 在编辑器中打开 / 预览」的先例？工具层（tool-fs / terminal）有没有暴露对应命令？先查 `docs/design/dsh-capabilities.md` 与官方包源码 |
| Q3 | **安全边界**：只允许打开任务工作区内的文件？ | 绝对路径白名单（工作区 `path` 前缀）· 任意路径放行（用户自己装的环境自己负责） |
| Q4 | **产出物展示形态**（场景 2） | 任务页列 `outputs` 文件清单 → 点击走 Q1 的动词；产出详情是否需要内容预览（md 渲染 / 代码高亮）还是只给打开入口 |
| Q5 | **与回执链路的关系** | 决策 19④：`outputs` 当前是逗号串路径（升级 JSON 已拍板暂缓）；产出物展示以回执里的 outputs + 真实文件存在性为准，不读文件内容当状态 |
