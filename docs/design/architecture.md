# 架构总览

三层分工：**调度层**（控制平面）/ **执行层**（数据平面）/ **记忆层**。

```
┌─ 调度层（控制平面）───────────────────────────┐
│  DSH host 层插件（本仓库）                      │
│   · 每 5 min tick，纯程序逻辑，零 token        │
│   · 读任务定义表 → 判时间 + 判前置 → 派发      │
│   · 订阅会话事件流 → 对账 → 写状态             │
└───────────────────┬───────────────────────────┘
                    │ ctx.sessions.create({工作区, 模型})
                    ▼
┌─ 执行层（数据平面）───────────────────────────┐
│  DSH 独立会话（每次干净会话，非子 agent）      │
│   · 按 target_workspace 落到对应工作区         │
│   · 读任务手册 MD → 干活 → 写产物 + 契约文件   │
│   · 不碰任务状态（只有调度器能写状态）         │
└───────────────────┬───────────────────────────┘
                    ▼
┌─ 记忆层 ──────────────────────────────────────┐
│  Hindsight（项目专属 bank）                    │
│   · 跨会话连续性靠记忆，不靠长命会话历史       │
└───────────────────────────────────────────────┘
```

三层与 DSH 既有分层呼应：L1 感知 = 调度层对账，L2 决策 = 执行层 agent 判断，L3 执行 = 具体动作。

## 分层职责边界

| 层 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 调度层 | 本插件（进程内） | 读任务定义、判定时序与依赖、派发会话、写任务状态、回收租约 | 不做需要判断的业务动作 |
| 执行层 | 一次性 DSH 会话 | 读手册、调工具/模型、写**产物文件**与契约文件 | **不写任务状态**（见 [decisions.md](decisions.md) 决策 11） |
| 记忆层 | Hindsight bank | 为执行层提供跨会话上下文 | 不承载必须确定性挂载的铁律 |

## 关键约束

- **调度层零大模型介入**：调度逻辑是纯程序逻辑，一行 token 都不该烧；只有执行层的某个任务才唤起模型。
- **状态单向写入**：只有调度器能写任务状态，agent 只能通过产物文件间接影响判定。
- **会话列表不是任务日志**：派发时用 `ctx.sessionTitle.rename` 起规范名（如 `[TASK] 镜像升级日报 · 2026-09-20`），跑完归档；真源始终是产物目录与 SQLite 状态表。
