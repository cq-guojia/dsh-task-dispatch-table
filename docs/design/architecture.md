# 架构总览

> **状态**：✅ 定型（使用中）
> **来源**：架构设计 + 决策 1/3/4/5/11 选型结论
> **配套**：数据见 [`data-model.md`](data-model.md)；功能清单见 [`features.md`](features.md)

三层分工：**调度层**（控制平面）/ **执行层**（数据平面）/ **记忆层**。

```
┌─ 调度层（控制平面）───────────────────────────┐
│  DSH host 层插件（本仓库）                      │
│   · 每 5 min tick，纯程序逻辑，零 token        │
│   · 读任务定义表 → 判时间 + 判前置 → 派发      │
│   · 订阅会话事件流 → 对账 → 写状态             │
└───────────────────┬───────────────────────────┘
                    │ ctx.agents.create({工作区, 模型, preset})
                    ▼
┌─ 执行层（数据平面）───────────────────────────┐
│  DSH 独立会话（每次干净会话，非子 agent）      │
│   · 按 target_workspace 落到对应工作区         │
│   · 读任务手册 MD → 干活 → 写产物 + 交回执     │
│   · 不碰任务状态（只有调度器能写状态）         │
└───────────────────┬───────────────────────────┘
                    ▼
┌─ 记忆层 ──────────────────────────────────────┐
│  Hindsight（项目专属 bank）                    │
│   · 跨会话连续性靠记忆，不靠长命会话历史       │
└───────────────────────────────────────────────┘
```

三层与 DSH 既有分层呼应：L1 感知 = 调度层对账，L2 决策 = 执行层 agent 判断，L3 执行 = 具体动作。

## 分层职责边界

| 层 | 谁 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 调度层 | 本插件（进程内） | 读任务定义、判定时序与依赖、派发会话、写任务状态、回收租约 | 不做需要判断的业务动作 |
| 执行层 | 一次性 DSH 会话 | 读手册、调工具/模型、写**产物文件**、执行插件下发的回提命令（决策 19，只记录不裁决） | **不写任务状态**（见 决策记录（已并入各专题文档） 决策 11） |
| 记忆层 | Hindsight bank | 为执行层提供跨会话上下文 | 不承载必须确定性挂载的铁律 |

## 关键约束

- **调度层零大模型介入**：调度逻辑是纯程序逻辑，一行 token 都不该烧；只有执行层的某个任务才唤起模型。
- **状态单向写入**：只有调度器能写任务状态，agent 只能通过产物文件间接影响判定。
- **会话列表不是任务日志**：派发时用 `ctx.sessionTitle.rename` 起规范名（如 `[TASK] 260928-1600 · 镜像升级日报；attempt>0 追加「 · 第N次」，源码 tasks.ts sessionTitleOf），跑完归档；真源始终是产物目录与 SQLite 状态表。⚠️ 归档后该会话被宿主**从所有分组面隐藏**（`archivedSessionIds`），无法再从 UI 打开；要回看只能读会话日志（决策 28，待落码）。
- **执行层的工具与系统提示词不由本插件决定**（决策 23）：派发时挂**部署默认 agent preset**，与用户 UI 新建会话同一套——工具集、prompt sections、skill 目录（含工作区 `AGENTS.md`）全部来自该 preset 的 composition；插件里不写死任何工具名。

## 关键约束（自历史决策并入）

- **调度层必须是进程内插件**，不引外部工作流引擎（n8n 之类）：它们的价值在 SaaS 连接器与可视化编排，本场景用不上，且感知不到 agent 执行状态。
- **不再绕 ACP**：已在进程内就直调 `ctx` API。
- **不用 subagent 派发**：`inheritsParentContext:false` 且 cwd 继承父会话 ⇒ 结构上派不到另一个工作区。
- **不用现成同类任务插件**：自研更可控。
- **手册分层**：短指令进 prompt；任务长手册放工作区 MD、只记路径；跨任务铁律放 `AGENTS.md`；**只有「既要自动任务用、又要人手动问」的流程才做 skill**。
