### 二、架构取舍（本轮拍板）

- **指令文本抽 `src/instructions.ts` 单一真源**：`description` / 权威段 / 派发【执行约束】/ goal objective / 追问声明全部只引用常量；冒烟断言改成钉「引用了同一常量」而非钉原话。不做「两处各改一遍文案」——那正是 P1 的成因。

- **路径绝对化只发生在两个边界**：回执写交付事件时（服务端，基准 = 派发冻结的 `workspacePath`）；客户端 `outputsOf` 读实例行时（基准 = 行快照 `workspacePath`）。存储层 `task_events` / `task_instances.outputs` **继续保持相对**，零数据迁移；`openFile` 与 4 个 UI 组件签名不动。
- **不做服务端自动折叠目录**：`docs/data/model.md:39` 既定「分桶由提示词驱动大模型判断（程序不猜）」；折叠会误伤共用目录、下游只注入主文件、含纳关系与模型声明四类合法情形。
- **安全闸做纵深两道**：回执入口过滤（不写库、不进卡）+ 对账 `checkReceipt` 复核（覆盖历史与绕过）。过滤如实告知丢弃项数，不静默丢。
- **手册不动**：本轮范围只在本仓库；手册的校验器死结与 Docker MCP 终态缺口另案。
